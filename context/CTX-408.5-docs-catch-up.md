# CTX-408.5: The Docs Describe An App That Changed

> **Spec Reference:** Links to
> [SPEC-408](../specs/SPEC-408-messaging-for-the-maker-who-is-leveling-up.md)

Reported by the maintainer: *"the documentation is stale… parts describing kicad must be open or
that the app can determine if a schematic is open are still in the docs."*

The audit found more than stale phrasing. **The docs are organised around KiCad's live IPC as the
main path, and it has become the minor one.** ERC, DRC, schematic reading, the netlist, board
geometry, the enclosure and all eight consideration packs now work on closed files. IPC is left
holding four things: writing a footprint into an open board, listing open boards, resolving 3D model
paths, and the live-board enclosure route that a file-based one already duplicates.

Two claims are not merely dated but **false**, and both sit in the place a sceptical reader goes to
find out what the app cannot do.

## 1. Feature Definition & Execution Plan

### Phase 1: A test that fails when the docs contradict the daemon — DONE

*   [x] Tie specific "not built" claims to the routes that falsify them.
*   [x] Fail loudly, naming the page and the route, so the next drift is caught by CI rather than by
      a user reading it.
*   [x] Written **before** the corrections, so it is seen failing on the real stale text.

### Phase 2: Correct every stale capability claim — DONE

*   [x] `what-it-is.md` no longer lists reading a schematic under what is not built.
*   [x] `board-checks.md` no longer says there is no review that volunteers concerns.
*   [x] `board-checks.md` no longer says a schematic must be picked every time.
*   [x] `install.md`, `first-run.md` and `built-on.md` describe the IPC server as what it now is:
      needed for a few live-session features, not for the app to read your work.
*   [x] `enclosure.md` and `footprints.md` stop presenting the live board as the primary route.

### Phase 3: The tutorial, rebuilt around what the app teaches

*   [ ] Stop touring tabs. The current shape walks Overview, PCB, Schematic, Enclosure in order,
      which is the app's navigation rather than the user's question.
*   [ ] Lead with what the app noticed about the reader's own board and why each finding matters.
*   [ ] Keep every command and path verifiable against the real example project.

### Phase 4: A shot list someone can actually hold a camera to

*   [ ] `SCREENSHOTS.md` describes reality: which existing shots are dead and why, which surfaces
      are new since 2026-09-04 and have never been captured.
*   [ ] Per-shot setup state, since several new surfaces only appear when a project is in a
      particular condition.

## 4. Deviations & Discoveries (Plan Drift)

*   **The guard caught my own mistake on its first run, before it ever saw a docs page.** I wrote
    `schematic.list_components` in the table; the real route is `kicad.list_schematic_components`.
    `TEST-005` — the row asserting every named route exists — failed immediately.

    Without it that row would have been permanently disarmed: a phrase paired with a route that
    never matches can never fire, and the test would have passed forever while guarding nothing.
    That is `CLAUDE.md`'s *"a check that cannot fail is not evidence"*, and it cost one line to
    prevent.

*   **Written before the corrections, and it failed on all five real claims**, naming page and
    route:

        what-it-is.md says "reading your schematic's contents", but the daemon registers
          'kicad.list_schematic_components'
        guides/board-checks.md says 'no ai review of your schematic', but the daemon registers
          'project.considerations'

    Seeing it fail on the genuine stale text is the only way to know the phrases match what is
    actually written rather than what I remembered writing.

*   **The rot was structural, not a set of dated sentences.** The docs are organised around KiCad's
    live IPC as *the* way the app works — `built-on.md`'s "How it talks to KiCad" opened with
    *"Over KiCad's own IPC API… The app connects to a running KiCad instance"* — and that has
    quietly become the minor path. ERC, DRC, connectivity, board geometry, the enclosure and all
    eight consideration packs read files with KiCad closed. IPC is left with four things.

    So `install.md` and `built-on.md` needed reordering, not patching: files first, IPC second and
    explicitly optional, with the four live-session features listed by name.

*   **The biggest new capability had no page at all.** Eight consideration packs, the claim classes,
    the trigger discipline and the guided-path toggle were documented nowhere. `board-checks.md`
    said the opposite — *"no AI review of your schematic yet… real planned work"* — which is the
    single most misleading sentence on the site, because it sits where a sceptical reader goes to
    find out what the app cannot do.

    Added `guides/what-it-notices.md`, and a homepage card, since the four existing cards described
    an app without its most distinctive feature.

*   **Two pages I expected to be wrong were already right.** `guides/enclosure.md` leads with the
    file-based route and mentions the live board second; `guides/footprints.md` correctly frames
    injection as the one genuinely live feature. Worth recording, because the audit's value depends
    on it having actually checked rather than assumed a uniform rot.
