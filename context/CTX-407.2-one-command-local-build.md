# CTX-407.2: One-Command Local Build

> **Spec Reference:** Links to [SPEC-407](../specs/SPEC-407-sidecar-build-integrity.md)

`SPEC-407` §2.3's bundle-time checkpoint, built with the option to fix the problem rather than only
report it. Started from a maintainer objection that the alternative was worse than the bug:

> "i don't want to run all of these commands just to get a local app i can test. this is a lot of
> friction that would deter a contributor from trying to test as well"

That is right, and it revises `SPEC-406` §1's rejection of a wrapper — see §4.

## 1. Feature Definition & Execution Plan

### Phase 1: `ensure_sidecar.py` — decide whether the sidecar is usable

*   [x] Resolve the target triple, most trustworthy source first: explicit argument, then
    `TAURI_ENV_TARGET_TRIPLE`/`CARGO_BUILD_TARGET`, and only then `rustc -vV`'s host. Host is last
    deliberately — it is the build machine's arch and stays wrong when cross-compiling, the exact
    bug `CTX-402.4` found mislabelling the x86_64 release leg.
*   [x] Detect the committed placeholder exactly, not heuristically: all four carry a literal
    `PLACEHOLDER` marker behind a `#!/bin/sh` shebang, and a real PyInstaller binary is Mach-O, PE
    or ELF and never contains it. A bounded 4KB read, so a real 32MB binary is never slurped.
*   [x] Check the architecture on macOS by parsing the Mach-O header directly — magic plus
    `cputype`, including the fat/universal case — rather than shelling out to `file` or `lipo`.
    Non-Mach-O targets return an empty set and skip the check, so Windows and Linux never inherit a
    rule they cannot pass.
*   [x] `--check-only` reports without freezing, for a CI job that wants the freeze as its own step.

### Phase 2: `freeze_sidecar.py` — do the freeze

*   [x] Split from Phase 1 so the fast "is it already fine" path carries no dependency on it.
*   [x] Locate an interpreter PyInstaller will accept, preferring python.org's universal2 3.11 on
    macOS, and fail with the literal remedy — the `curl` and `installer` lines — rather than a
    vague "not found".
*   [x] Apply one architecture across venv creation, dependency install and the freeze, since
    `daemon.spec`'s `target_arch=None` means "match the invoking interpreter".
*   [x] Clear `.build-venv` and `build/` first. PyInstaller's cache can reuse a binary processed
    for the other architecture and turn a build-time error into a runtime `dlopen` failure — that
    is what happened on 2026-08-27.
*   [x] Rename to the target-triple name, the step whose omission bundles the placeholder.

### Phase 3: one command, one implementation

*   [x] `tauri.conf.json`'s `beforeBuildCommand` runs `ensure_sidecar.py` before the frontend
    build. Tauri's own hook; no new mechanism.
*   [ ] `release.yml`'s separate venv, pip, pyinstaller and `mv` steps collapse into one call to
    `freeze_sidecar.py`, plus an `--check-only` verification. **Written and validated, but NOT
    APPLIED** — this session's GitHub App token lacks the `workflows` permission, so the push was
    rejected. The change is committed as a patch at `docs/release-yml-spec-407.patch` for a
    maintainer to apply. See §4 Deviation 4: until it is applied, the "one implementation" property
    this design rests on is **not yet true**.
*   [x] `CONTRIBUTING.md` Tier 3 rewritten around the single command.

counts unchanged from the 460-test baseline captured before any work began.

**Not verified, and this is the significant gap.** No `tauri build` was run. The
`beforeBuildCommand` wiring is argued from evidence rather than executed: the existing
`npm run build --prefix ../apps/tauri-ui` demonstrably works in CI, which proves the hook's working
directory is `core/`, and the new path was checked to resolve from there. That is strong inference,
not a run. **The first real `tauri build` on a macOS machine is the test that matters, and it has
not happened.** Likewise no real freeze ran — `freeze_sidecar.py`'s own subprocess sequence is
unexercised end to end, and this container has neither a framework Python nor a Tauri toolchain.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1 — this revises an approved spec's stated non-goal, which needed the maintainer's
    decision rather than mine.** `SPEC-406` §1 explicitly rejected "a `Makefile`, `just` file, or
    wrapper script" for two reasons. The first — "a documented one-line command is the
    deliverable" — is falsified: that command produces a broken app, and did so seven ways in one
    session. The second — "a wrapper is a second thing to keep in sync with `release.yml`" — was
    the real constraint, and it shaped the design: `release.yml` calls the same script, so this is
    the *only* implementation where previously the sequence existed twice. The non-goal is marked
    superseded in `SPEC-406` itself with the reason, rather than deleted, because the reasoning was
    sound when written and what changed is the evidence.

*   **Deviation 2 — a path bug caught before it shipped, by checking rather than assuming.** The
    hook was first written as `../../services/python-daemon/scripts/ensure_sidecar.py`, reasoning
    from `tauri.conf.json`'s own location. That would have broken **every** build. The existing
    `--prefix ../apps/tauri-ui` is the evidence that settles it: it works in CI today, and it only
    resolves if the hook's working directory is `core/`, one level above the config. Corrected to a
    single `../` and both paths confirmed to resolve from there. Recorded because the wrong version
    looked more correct — config paths in this file *are* relative to the config, just not command
    paths.

*   **Deviation 3 — the freeze is now automatic, which trades one friction for another.** A first
    build on a machine without a framework Python still stops, and on macOS the remedy involves
    `sudo installer`. That is a hard stop the previous design did not have, because the previous
    design silently produced a broken app instead. Strictly better, but not frictionless, and worth
    stating plainly rather than claiming one command always works.

*   **Deviation 4 — the `release.yml` half could not be pushed, so the central claim is not yet
    true.** The design answers `SPEC-406` §1's "second thing to keep in sync" objection by making
    `release.yml` call the same script. That edit was written, validated as YAML, and committed —
    and then rejected on push: *"refusing to allow a GitHub App to create or update workflow
    `.github/workflows/release.yml` without `workflows` permission"*. It was reverted from the
    branch rather than worked around, since that permission gate exists precisely to stop an agent
    silently rewriting CI, and preserved as `docs/release-yml-spec-407.patch`.
    *   *Impact, stated plainly:* until a maintainer applies that patch, the freeze sequence exists
        in **two** places — `freeze_sidecar.py` and `release.yml`'s own steps — which is the exact
        duplication `SPEC-406` §1 warned about. The local-build half of this context stands on its
        own and is a real improvement regardless; the deduplication that justifies overriding the
        non-goal does not land until the patch does. `SPEC-406`'s superseded marker is therefore
        slightly ahead of reality, and should be re-read once the patch is applied.

*   **Non-deviation, checked rather than assumed:** the placeholder marker was verified present in
    all four committed placeholders on disk before being relied on, and `TEST-002` asserts against
    those real files rather than a copy, so the check cannot rot silently if a placeholder is
    regenerated.
