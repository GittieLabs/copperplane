# CTX-405.3: Implementation Context: Identity-Guard Tests

> **Spec Reference:** Links to [SPEC-405](../specs/SPEC-405-product-rename-copperplane.md)

**Deliberately landed first, out of the module map's own numeric order** (`CTX-405.1`/`.2` are the
actual mechanical rename; this is `.3`). SPEC-405 §3.4 calls the three identity-guard tests "the
durable artifact" of the whole spec and names the exact hazard they exist to catch: a global
find-and-replace during the rename silently orphaning every existing user's keys, linked projects,
and generated footprints. Landing the guard *before* any renaming touches a single file means the
very next phase (the actual 75-file sweep) has a real, immediate tripwire from its first commit
onward, rather than a tripwire added only after the risky work is already done.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1: this phase was sequenced before `CTX-405.1`/`.2`, out of the spec's own module-map
    order.**
    *   *Reasoning:* SPEC-405 §3.4 names these tests as the mitigation for its own central,
        explicitly-named hazard ("a global find-and-replace... will orphan every existing user's
        keys, library and linked projects"). A mitigation that lands only after the risky work is
        already done protects nothing during the work itself.
    *   *Impact:* `CTX-405.1`'s eventual 75-file sweep can run with these five tests already green
        and already failing loudly on the very first accidental touch of a frozen string, rather
        than needing its own commit to add the safety net partway through.
