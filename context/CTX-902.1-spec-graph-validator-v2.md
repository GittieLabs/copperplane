# CTX-902.1: Spec Graph Validator v2

> **Spec Reference:** Links to [SPEC-902](../specs/SPEC-902-spec-graph-validator-v2.md)

## 1. Feature Definition & Execution Plan

### Phase 1: Fix the path-exclusion matcher (real, currently-triggering bug)
*   [x] Replace bare `str.startswith(...)` in `EXCLUDE_PATHS`/`CODE_EXTENSIONS` with real
    path-segment/basename matching: exempt any `README.md` by basename (not just root), any path
    with a `.github`/`specs`/`context` directory component at any depth, and lockfiles
    (`package-lock.json`, `Cargo.lock`, `uv.lock`) by basename.

### Phase 2: Parse `SPEC-*.md` frontmatter
*   [x] Reuse the existing `parse_frontmatter()` (already generic — it just reads YAML between
    `---` fences) to discover and parse every `SPEC-*.md` in the repo, not only the ones changed in
    the current diff.

### Phase 3: Graph-integrity checks (hard failures)
*   [x] `id` uniqueness across every discovered spec.
*   [x] `id` matches the file's own name (`SPEC-902` must live in a file named `SPEC-902-*.md`).
*   [x] `location:` frontmatter field matches the file's actual path relative to the repo root.
*   [x] Every `parent_spec`/`child_specs` path resolves to a real file on disk, resolved relative to
    the referencing file's own directory (matching how the markdown links in the same files work).
*   [x] Bidirectional check: if `A.parent_spec` points at `B`, `B.child_specs` must list `A` back.
*   [x] Extend the existing `CTX-*.md` check so `spec_ref` also resolves to a real file (today the
    validator only checks the field is *present*, never that its path is real).

### Phase 4: Informational findings (never block)
*   [x] Report specs with no matching `CTX-*.md` context file anywhere in the repo ("no context
    yet") and specs with `parent_spec: null` that aren't `SPEC-000`/`SPEC-901`/`SPEC-902`/`SPEC-903`
    (a soft "orphan" signal). Printed in the report; never contributes to the exit code.

### Phase 5: Real test coverage for a script that gates every future PR
*   [x] `scripts/tests/test_validate_spec_context.py`: unit tests for the new path-matcher against
    real repo paths (root/module README, lockfiles, nested `specs/`/`context/` dirs, ordinary code
    files), unit tests for each new graph check against constructed fixture files in a temp
    directory (never against this repo's own real `specs/`/`context/` trees), and **one true
    end-to-end test**: a real temporary git repo, a real commit history, a deliberately broken spec
    file, and the actual CLI invoked via `subprocess` — asserting the real exit code and error
    text, not just a helper function's return value.
*   [x] Confirm every existing check (`CTX-*.md` frontmatter/hashes/testing-matrix) still passes
    against this repo's real, current state after the change — this script must keep working for
    every PR that comes after this one, including ones this session already opened.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1: `ROADMAP.md` §1.3's specific claim about module READMEs doesn't actually
    reflect a live bug — verified directly before writing any fix.**
    *   *Reasoning:* Tested the real matcher logic with `services/python-daemon/README.md` and the
        root `README.md` as input before touching any code: both produced `counts_as_code=False`,
        identically, because `.md` was never in `CODE_EXTENSIONS` to begin with — the
        `EXCLUDE_PATHS` check is never even reached for either. The roadmap's framing of this as an
        active bug doesn't hold up under direct testing.
    *   *Impact:* Fixed the underlying mechanism anyway (real path-segment/basename matching
        instead of bare `str.startswith`), since it's still wrong in principle and would bite the
        moment a non-`.md` file ever lands under a module-level `specs/`/`context/` dir. But the
        `.json` lockfile claim in the same roadmap paragraph *is* real and currently triggering —
        confirmed directly the same way before fixing it. Worth remembering as a pattern: two
        claims presented with equal confidence in the same bullet list were not equally true.

*   **Deviation 2: the whole-graph check runs on every invocation, not only when a PR's diff
    touches a `SPEC-*.md` file — a deliberate scope decision beyond what `SPEC-902` §2 stated.**
    *   *Reasoning:* `SPEC-902`'s own Gotcha says the check must cover the whole graph, not just the
        diff, because a change to `SPEC-A`'s `child_specs` can break a link *from* `SPEC-B` that
        this PR never touched. Taken to its logical conclusion, that means the graph's validity is
        an invariant that should hold on every run, regardless of what a given PR happens to touch —
        a code-only PR that never touches any spec should still be protected if the graph is
        somehow already broken. The cost is negligible (reading and parsing eight small YAML
        frontmatter blocks) compared to the value of catching drift immediately rather than only on
        PRs that happen to touch `specs/`.
    *   *Impact:* `validate_spec_graph()` is called unconditionally in `validate_pr()`, not gated
        behind `if spec_files_changed`. Confirmed via `TEST-006` that this doesn't introduce any
        false positive against the repo's real, current state.

*   **Deviation 3: this script gates every PR in the repo, including this one's own — verified
    the CLI contract is unchanged before relying on that.**
    *   *Reasoning:* `.github/workflows/spec-container-gatekeeper.yml` invokes
        `python scripts/validate_spec_context.py --base origin/$BASE_REF` with no other changes
        needed for this spec — confirmed by re-reading the workflow file rather than assuming the
        CLI surface (`--base` flag, exit codes, stdout format) was preserved. `TEST-006` and the two
        end-to-end `subprocess` tests (`TEST-005`, `TEST-007`) are what actually prove this, not just
        a read-through of the diff.
    *   *Impact:* None — confirms the contract held. Noted because a script this load-bearing
        deserved the extra confirmation step rather than trusting the diff looked reasonable.
