# CTX-902.3: Implementation Context: Trivial-Fix Contributor Lane

> **Spec Reference:** Links to [SPEC-902](../specs/SPEC-902-spec-graph-validator-v2.md)

The change that makes outside contribution possible. `scripts/validate_spec_context.py` currently
fails any PR touching a code extension outside `specs/`/`context/`/`.github/` unless it carries a
full `CTX-*.md` -- correct for feature work, a brick wall for a stranger fixing a typo. This context
adds a real, working `trivial-fix` label bypass, exempts a planned `docs/` site from the code check,
and closes a real, live gap where `status:` was a required key whose *value* was never checked --
35 of 42 real spec files said `Draft`, including specs shipped months ago. It also lands the
contributor-facing documentation (`CONTRIBUTING.md`, PR/issue templates, `NOTICE`, `SECURITY.md`,
`CODE_OF_CONDUCT.md`) that describes these lanes as though they already worked -- they didn't, until
this context. `scripts/validate_spec_context.py` is itself a `.py` file under `scripts/`, which is
not exempted -- changing the validator trips the validator, which is why this PR needs its own
context file.

## 1. Feature Definition & Execution Plan

### Phase 1: The `trivial-fix` label bypass
*   [x] `validate_pr(base_branch, labels=None)` -- a new `labels` parameter (a real `set`), never
    fetched from the GitHub API by this script itself: passed in from the workflow via a new
    `--labels` CLI argument, which the workflow populates from
    `${{ join(github.event.pull_request.labels.*.name, ',') }}`. Keeps the script runnable offline
    and unit-testable with no real token or network call.
*   [x] The bypass is scoped to exactly RULE 1 (the missing-context-file check) -- when
    `'trivial-fix' in labels`, that one check is skipped; the spec-graph validation, the Testing
    Matrix/commit-hash checks on any context file the PR *did* touch, and the test/lint jobs in the
    other workflows are all unaffected and still run. When it fires, it prints a real, visible
    `⚠️  SKIPPED` line naming the label and stating that tests/lint still ran -- a silent bypass is
    how this becomes a hole nobody notices.
*   [x] `.github/workflows/spec-container-gatekeeper.yml`: passes `PR_LABELS` through as an env var
    and forwards it as `--labels "$PR_LABELS"`. The workflow's own trigger already included
    `labeled`/`unlabeled` in its `types:` list -- someone anticipated this and never finished it;
    this closes that gap, not invents a new one.

### Phase 2: Let the docs site exist
*   [x] `EXCLUDE_DIR_NAMES` gains `'docs'`. Confirmed directly, not assumed, that this is safe for
    *this* repo: the existing exclusion mechanism matches a directory name at any depth (the same
    behavior `.github`/`specs`/`context` already have), so this also exempts any directory literally
    named `docs` anywhere in the tree -- checked directly (`find . -type d -name docs`) and only the
    one, intended `docs/` at the repo root exists today.

### Phase 3: Make `status:` mean something
*   [x] `ALLOWED_SPEC_STATUSES = {'Draft', 'Approved', 'In-Progress', 'Completed', 'Deprecated'}`,
    matching `SPEC-TEMPLATE.md`'s own enum (which itself was missing `Completed` -- added as a small,
    while-I'm-here consistency fix). Checked inside `validate_spec_graph()`'s existing per-file loop,
    repo-wide, same as the other structural spec checks.
*   [x] `SPEC-TEMPLATE.md` needs no explicit filename exemption: confirmed directly (not assumed)
    that `find_all_spec_files()`'s own `glob('**/specs/SPEC-*.md')` never matches it in the first
    place, since its real path is the repo root, not any `specs/` directory. The instruction to
    "exempt the template by filename" turned out to already be true by construction -- recorded
    here rather than adding a redundant, dead defensive check for a case that structurally can't
    occur.
*   [x] **Real-data sweep**, using `ROADMAP.md` as the source of truth per its own §1.1 "Built and
    recorded" table and §3's per-spec backlog headers, never re-derived: 28 specs corrected from
    `Draft` to `Completed` (SPEC-101/102/103/104/105/106/107/108/109/110/201/202/204/301/302/303/
    304/305/306/307/312/313/314/315/316/402/901/902/903), one to `In-Progress`
    (SPEC-205, matching ROADMAP's own "🚧 in progress" marker). Left unchanged, honestly, because
    ROADMAP itself records no explicit completion for them: SPEC-300, 308, 309, 310, 311, 317 (all
    real, substantially-built specs per this repo's own extensive `CTX-3xx.*` history, but not
    something this task should silently derive rather than cite) and SPEC-904 (actively being
    authored by a separate, concurrent session at the time of this sweep).

### Phase 4: Land the documentation
*   [x] `CONTRIBUTING.md` (full rewrite), `NOTICE` (real Apache-2.0 §4(d) compliance fix --
    propagates AgentFlow's and Requests' own NOTICE text, which the previous version omitted
    entirely), `SECURITY.md`, `CODE_OF_CONDUCT.md` -- all drafted in a separate, concurrent session,
    already on disk as untracked files, committed here verbatim.
*   [x] `.github/PULL_REQUEST_TEMPLATE.md`, `.github/ISSUE_TEMPLATE/{bug_report,platform_report,
    feature_request,config}.yml` -- drafted the same way but could not be written to disk directly
    (the remote bridge that session used refuses writes under `.github/`); provided verbatim and
    written here instead. None of these need a context entry of their own -- `.github/` is already
    in `EXCLUDE_DIR_NAMES`.
*   [x] Three labels the templates reference (`needs-triage`, `platform`, `incorrect-advice`) do not
    exist on GitHub yet and need to be created there directly -- not something this script or its
    tests can do; named here as real, separate follow-up, not silently assumed done.

### Phase 5: Tests
*   [x] `scripts/tests/test_validate_spec_context.py`: `TestTrivialFixLabelBypass` (5 tests, real CLI
    via subprocess against a real git repo, matching `TestEndToEndCLI`'s own established pattern) --
    label absent still raises `CRITICAL`; label present suppresses it; the skip message is really
    printed; an unrelated label bypasses nothing; the label never bypasses a genuine spec-graph
    error (a dangling `parent_spec`) even when present. `TestPathExclusionMatcher` gained a `docs`
    depth test. `TestSpecStatusValue` (3 tests) covers every allowed value passing, an unrecognized
    value being a hard error, and a plausible-looking typo (`completed` lowercase) still being
    caught -- the real, motivating bug this whole check exists to close.
*   [x] Full suite: `python3 -m unittest discover scripts/tests` -- **79 passed**, 0 failures,
    including `TestAgainstRealRepo`, confirming the 30-file status sweep didn't introduce a single
    new hard error against this repo's own real, current graph.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1 (non-deviation, confirmed as designed): `SPEC-TEMPLATE.md` needed no explicit
    filename exemption for the new status check.**
    *   *Reasoning:* the task's own instructions anticipated this as a real problem ("SPEC-TEMPLATE.md
        itself carries the literal placeholder line ... and will fail the new check"). Verified
        directly before writing a fix: `find_all_spec_files()`'s glob (`**/specs/SPEC-*.md`) never
        matches `SPEC-TEMPLATE.md` at all, because its real path is the repo root, not inside any
        `specs/` directory. The anticipated failure mode doesn't exist; adding a defensive exemption
        for it anyway would be dead code for a case that structurally can't occur.
    *   *Impact:* none -- `SPEC-TEMPLATE.md`'s own placeholder enum was still updated to add
        `Completed` for documentation consistency, independent of this finding.
*   **Deviation 2 (non-deviation, confirmed as designed): five specs (SPEC-300/308/309/310/311/317)
    were left `Draft` despite being substantially built, per this session's own direct knowledge.**
    *   *Reasoning:* the task's own instruction was explicit -- "`ROADMAP.md` already records what
        is done, per spec, with dates — use it as the source of truth rather than re-deriving." None
        of these six specs has an explicit completion marker anywhere in `ROADMAP.md` (checked
        directly, not assumed) -- a real, separate documentation gap in `ROADMAP.md` itself
        (the same class of gap `SPEC-317` was already found to have, earlier this session), not
        something this sweep should silently paper over by inferring completion from CTX-file
        counts instead of the named source of truth.
    *   *Impact:* these six specs still read `Draft` after this context. A future pass that first
        fixes `ROADMAP.md`'s own missing entries for them, then re-runs this sweep, is the correct
        order -- not guessed at here.
*   **Deviation 3 (non-deviation, confirmed as designed): SPEC-904 was left `Draft` even though it
    plausibly relates directly to this same PR's `NOTICE` work.**
    *   *Reasoning:* a separate, concurrent session was actively authoring `NOTICE`/`SECURITY.md`/
        `CODE_OF_CONDUCT.md`/`CONTRIBUTING.md` at the time of this sweep -- changing SPEC-904's own
        status mid-flight, without knowing that session's own intent for it, risked colliding with
        work already in progress elsewhere.
    *   *Impact:* none today; a real, named item for whoever closes out SPEC-904's own work to
        update its status then, not here.
