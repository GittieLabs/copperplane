# CTX-402.7: Implementation Context: Release Notes Ancestry Fix and CLI Version Pin

> **Spec Reference:** Links to [SPEC-402](../specs/SPEC-402-release-signing-and-auto-update.md)

Found immediately after `CTX-402.6` shipped: the real `v0.2.0` GitHub Release published successfully
but its body read "No CTX-*.md changes between bc5acf8...and v0.2.0" -- despite ~140 real commits
since `v0.1.3`. Two real, compounding bugs, plus the version-pin gap `CTX-402.6`'s own Plan Drift had
already named as unaddressed.

## 1. Feature Definition & Execution Plan

### Phase 1: diagnose the empty release notes
*   [x] `generate_release_notes.py`'s `latest_tag()` walked git ancestry (`git describe --tags
    --abbrev=0 {ref}^`) to find "the previous release." Confirmed directly: `origin/main` was frozen
    on 2026-08-19 (last real commit, PR #161, "SPEC-312" era) while every real feature since --
    SPEC-313 onward, the entire product surface this session built on -- landed on `develop` alone.
    `v0.1.3` was tagged from `main`'s lineage; `v0.2.0` was tagged from `develop`'s. `git
    merge-base --is-ancestor v0.1.3 04721e2` returns false -- confirmed by direct command, not
    inferred. `git describe` correctly found no ancestor tag at all.
*   [x] The fallback (`first_commit()`, used when `latest_tag()` returns `None`) also failed: the
    `publish` job's `actions/checkout@v4` step had no `fetch-depth`, defaulting to a shallow
    depth-1 clone. With only one commit fetched, git has no parent info for it at all, so `git
    rev-list --max-parents=0 v0.2.0` returned that single commit's own hash back -- exactly the SHA
    the real, broken release notes printed as `from_ref`.
*   [x] Discussed with the maintainer whether `main` should be brought back in sync with `develop`
    or left alone, since GitHub's own default branch is already `develop` -- decided to leave `main`
    as-is. The fix therefore cannot assume every tag shares one branch's ancestry going forward.

### Phase 2: the fix
*   [x] `latest_tag()` rewritten to find the most recent *other* real tag by **creation date**, not
    ancestry -- resolves both `before_ref` and each candidate tag to a real commit SHA and skips any
    tag pointing at the same commit `before_ref` does (a strict superset of the old "don't self-select
    the tag on before_ref" guard, since it compares by resolved commit rather than by ref name, and
    doesn't require `before_ref` to be a git descendant of anything). This is what "since the last
    release" actually means to a human, independent of which branch either tag happened to be cut
    from.
*   [x] `.github/workflows/release.yml`'s `publish` job's checkout gains `fetch-depth: 0` (full
    history) -- needed regardless of the ancestry-vs-date question, since a real `from_ref..to_ref`
    diff needs real history to walk at all.
*   [x] All three `tauri build` invocations in `release.yml` now pin `@tauri-apps/cli@2.11.4`
    (the exact version `CTX-402.6`'s own real, successful re-run just verified end to end),
    replacing the floating `@tauri-apps/cli@2` that let `npx` silently resolve whatever `2.x` was
    newest at build time -- the actual root cause of `CTX-402.6`'s Linux updater-artifact regression.
    Deliberately scoped to the release build steps only, not every `tauri dev`/local-build mention
    across `README.md`/`CONTRIBUTING.md`/`docs/site` -- those never produce a distributable artifact,
    so version drift there has no "silently wrong file shipped" consequence, and pinning them would
    be maintenance churn with no matching safety benefit (see Plan Drift).

### Phase 3: tests
*   [x] `scripts/tests/test_generate_release_notes.py`'s shared `_commit_file` helper now sets
    explicit, strictly increasing `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` per commit -- git's
    1-second timestamp resolution made a fast test suite's real wall-clock commit order a real
    flakiness risk once `latest_tag()`'s correctness started depending on creation-date order, where
    it previously didn't.
*   [x] New test: two branches diverging from a common ancestor, an old tag on one (never merged
    back) and a new tag on the other -- the exact real-world shape `main`/`develop` are in today.
    Asserts the real test-setup invariant (`git merge-base --is-ancestor` returns false) before
    asserting `latest_tag()` still finds the old tag by creation date.

## 4. Plan Drift & Architectural Changes

*   **`main` is left frozen, by the maintainer's own explicit decision.** Considered and rejected:
    fast-forwarding `main` to `develop`, or deleting it. `develop` is already GitHub's default branch
    and everything (this whole session's workflow, `CONTRIBUTING.md`'s documented loop) already
    treats it as the real trunk -- `main` is a historical artifact, not a live risk, and the fix here
    (compare by date, not ancestry) is what makes the release pipeline correct regardless of that
    decision, rather than depending on it being reversed.
*   **The CLI version pin is scoped to `release.yml`'s three build steps only, not every `tauri dev`/
    local-build doc mention.** Reasoning: the real, observed harm (`CTX-402.6`) was a *distributable
    artifact* silently produced in a subtly wrong shape by a drifted CLI version -- a risk that exists
    only where a real release artifact gets built and published. A contributor's own `tauri dev` or
    local Tier-2/Tier-3 build (`SPEC-406`) has no such consequence; pinning those too would be
    maintenance churn (every real version bump needing edits across `README.md`, `CONTRIBUTING.md`,
    `apps/tauri-ui/README.md`, `core/tauri-rust/README.md`, `docs/site/...`) with no matching safety
    win. Named explicitly here as a deliberate scope decision, not an oversight.
*   **No dedicated test exists for the `fetch-depth: 0` checkout change itself** -- it's a one-line
    workflow YAML option with no local logic to unit-test; its correctness is proven by the real,
    end-to-end release run this context's own Phase 1 diagnosis already traced the failure to, and by
    the next real tag-triggered run this fix is meant to unblock.
