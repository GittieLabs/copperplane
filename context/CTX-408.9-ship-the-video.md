# CTX-408.9: Ship The Video, And The App It Shows

> **Spec Reference:** Links to
> [SPEC-408](../specs/SPEC-408-messaging-for-the-maker-who-is-leveling-up.md)

The maintainer watched the cuts (`CTX-408.7`, `CTX-408.8`) and said: "the videos look good". Then
they asked for three things:

- the video on GitHub and on the docs site;
- **a new release of the app, so the release build matches**;
- the videos hosted so they are easy to share and add to posts.

The second is the one the others depend on. The cuts were shot against a local build of `develop`
on 2026-10-10. The current release, v0.4.0 (2026-09-05), predates the board-check fix (SPEC-340)
and the Overview findings (SPEC-343), the two things the video demonstrates. Sending people from the
video to that download would show them an app that cannot do what they just watched.

### Phase 3: Verify the published app against the video

*   [ ] Download the **published** macOS build, not a local one. Confirm its sidecar answers, then
      confirm the findings the video shows on the example board:
      - A1's +5V on VIN;
      - 4 annular-width violations at 0.0850 against 0.1000 mm, plus 1 unconnected item;
      - D1's 2-pin symbol against its 4-pad footprint.

      It must be **pre-release and not latest**: the updater reads

      for every installed copy.

### Phase 5: The docs site and the README

*   [x] README: a poster frame linking to that page. GitHub does not play a repository MP4 inline.

### Phase 6: Verify as the user

### Phase 7: Before the traffic

## 4. Deviations & Discoveries (Plan Drift)

*   **Phase 7: "a local Ollama setup is the answer" for a maker with no key was wrong, and I
    nearly wrote the guide that said so.** The outreach plan assumed it, and so did I. Before
    documenting it, I drove the **frozen** sidecar (`dist/hardware-agent-studio-daemon-aarch64-apple-darwin`,
    which `ensure_sidecar.py --check-only` reports as current) over JSON-RPC. It ran against a real
    local Ollama (`llama3.2:1b`, the preset's default) on the example project, with a scratch
    `storage_root` so the maintainer's own config was untouched. Results:

    | Config | `kicad.check_schematic` | Explanations | `llm.chat` (Overview chat) |
    | :--- | :--- | :--- | :--- |
    | No provider | 2 findings | Failed; the summary carries the raw Anthropic SDK auth error | Same raw error |
    | `provider_roles` → ollama (what Settings writes) | 2 findings | Refused: `board_advisor` requires `strict_json` | **Called Anthropic anyway** |
    | Same, plus legacy `llm_provider: ollama` | 2 findings | Refused | Answered, from `llama3.2:1b` |

    `kicad.generate_component` (part lookup) on ollama was refused by the same capability gate.
    The user sees *"This usually means the part has an unusually long pin list. Trying again often
    works"*, which is wrong twice: it is not the pin list, and retrying cannot help.

    So the Install page says what is true today: the checks run with no model, the explanations do
    not, and Ollama is not yet the starting point. The product fixes are not in this context; they
    are application changes and need their own.
*   **Not verified as the user:** that the app's window renders the no-provider check result
    rather than an error state. The daemon returns findings with `explanations_failed: true` and a
    summary; I read no frontend code that gates on a provider, and did not click it.
*   **The 15 s cut on phones was confirmed, not assumed.** In the built site at a narrow viewport,
    the hero's `currentSrc` is `copperplane-15s-9x16.mp4`. The old label was wrong for every phone.
*   **The long cut is 61.5 s in all four aspects** (`ffprobe` on each). Its files keep the name
    `60s`: they are on a published release, and renaming them would break links already shared.
*   **The v0.7.0 release notes are generated, and they read as a log.** `release.yml` publishes
    `scripts/generate_release_notes.py`'s output: every changed `CTX-*.md` table, verbatim,
    including `CTX-113.4`'s withdrawn commit. The same text goes into `latest.json`, so the in-app
    updater shows it too. `docs/release-notes/v0.7.0.md` replaces it for this release only; the
    generator is unchanged and the next release will repeat this unless `SPEC-402`'s pipeline
    learns to prefer a hand-written file.

*   **The release is blocked by an expired Apple agreement, and only the maintainer can clear it.**
    The bump, the tag and the code were all fine. Signing succeeded and notarization failed.
    Re-running the failed jobs once the agreement is accepted reuses the Linux and Windows builds.
*   **The video release is `product-video-2026-10`: pre-release and not latest. Both are checked,
    not assumed.**
    - It does not match `release.yml`'s `v*` trigger, so it never starts a build.
    - After creating it, `releases/latest` still answered v0.4.0: the updater is untouched.
    - It carries 36 assets (12 cuts, each with a cover and an `.srt`). Each MP4 has a silent AAC
      track, and each was checked to keep its source's exact frame count.
    - My first attempt passed a short SHA as `--target`. GitHub refused it (422) and created
      nothing.
*   **GitHub serves release assets as downloads, not for playback.** `application/octet-stream`
    with `attachment`, so a `<video>` cannot rely on them. The site plays its own copies, committed
    under `docs/site/public/video/` (3.4 MB together). The release is the share and download
    source.
*   **The landing video first sat below the "Early, and honest" notice, past the first screen on a
    phone.** Seen in the browser pane at phone width, so it moved directly under the hero.
    Verified there:
    - it autoplays muted, and loads 1280×720 from the site's own copy;
    - the Watch page plays both cuts (30.0 s and 15.0 s);
    - all 12 download links return 200.
*   **"Update GitHub and the docs with the new logos": the brand zip held no new logos.**
    - All 71 logo files in `brand/copperplane-brand-revA.zip` are byte-identical to `brand/`. Only
      its README and two build scripts differ, and the repo's are newer.
    - The site's header logo and favicon were already the brand's own files.
    - What was actually stale was everywhere the brand *should* appear and did not:
      1. **The GitHub repo description** still read "Hardware Agent Studio is an open-source,
         local-first AI assistant...", the pre-rename name, shown on the repo page and in every
         link preview. Updated through the API to the README's line.
      2. **No link-preview image anywhere.** A shared docs link had no `og:image`, and the repo had
         no custom social preview. `docs/video/studio/card.html` draws one with the video's own
         canvas code: the lockup, the tagline, the cold open's finished PCB. It is wired in as the
         site's `og:image` and Twitter card on every page (checked in the built HTML), and saved
         as `docs/video/github-social-preview.png` (1280×640) for the repo's settings. That upload
         has no API.
      3. **The site-wide meta description** was the old engineer-facing line. It now matches the
         landing page.
*   **#482 was merged one commit early.** It merged at `6a5ec30`, before `a906664`, which
    reworded the Watch page's release claim and stopped the hold. So the live page still said
    the findings are "the ones the current release reports". `a906664` is carried into the
    hero-video PR (#483).
*   **The maintainer's first look at the live site: "I missed the video... it does not surface on
