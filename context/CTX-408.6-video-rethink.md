## 4. Deviations & Discoveries (Plan Drift)

*   **The script was good, and the instinct to rewrite it wholesale was wrong.** Its premise — *"KiCad
    tells them what is wrong in a language they do not speak, and stays silent about the thing that
    would cost them a board order"* — is more true now than when it was written, not less. What had
    expired was the **shape**: every beat opened with a click, because that was the only way the app
    ever said anything.

*   **The new beat is better video than it is a feature.** Link a project and Overview has already
    read the schematic's connectivity and has three things to say. The strongest possible
    demonstration of *"this is not a checker"* is a screen that speaks with nobody touching the
    mouse — so the segment's direction note is about the **cursor being visibly still**, since a
    cursor drifting toward a button undercuts the claim in a way no caption repairs.

*   **The finding chosen for it is a question, and the script now says so.** The `+5V`-on-`VIN`
    consideration ends by asking *is `+5V` what you meant here?*, because the app cannot see inside
    an Arduino module. Narrating it as a verdict would be both inaccurate and, for this audience,
    less persuasive: a tool that hedges where it should is more credible than one that never does.

*   **The old script asserted a finding count the recording cannot guarantee.** It said the list is
    *"five findings: three that explain DRC and two the next segment is about"*. Verified against the
    real project: DRC produces four annular-width violations plus one unconnected item, and the two
    structural mismatches are real — but the explanation pass is a model call that **groups related
    violations**, so the number on screen is not fixed between runs.

    The script already said *"do not put a findings count on screen"*, for a different reason. That
    warning is now also about its own arithmetic.

*   **The thirty-second advice inverted, and the reason is worth keeping.** It used to be hook →
    mismatch → close, on the argument that the mismatch is the only segment unique to this product.
    There are two such segments now, and the new one is the better single beat despite being the
    less sharp idea: the mismatch needs a viewer who already cares about the difference between
    *"breaks a rule"* and *"will not work"*, while a screen that answers before anybody asks needs no
    setup at all.
