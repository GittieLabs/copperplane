# CTX-407.4: Bundle the Agent Prompt Tree

> **Spec Reference:** Links to [SPEC-407](../specs/SPEC-407-sidecar-build-integrity.md)

A tenth sidecar failure mode, and the most consequential one yet: **every AI feature has failed in
every frozen build this project has ever shipped**, while working perfectly from source.

Reported from a real running app on 2026-09-01 — a component search returning, in red:

```
Context directory not found: /var/folders/.../T/_MEI0000db05QfHx3S/agentflow
```

## What was wrong

`chat_agents`, `component_pipeline` and `datasheet_guidance` all resolve the agent prompt tree as
`os.path.dirname(__file__)/agentflow`. Under PyInstaller that dirname is `sys._MEIPASS`, the
runtime extraction directory — **so the path was always correct for a frozen build.** There was
simply nothing extracted there: `daemon.spec` declared `datas=[]`.

`datas` has been empty since the spec was written in `CTX-401.1`, checked across every revision in
its history. So `component.search`, `chat.send`, `datasheet.generate_guidance` and
`kicad.generate_component` — twelve agents plus the router — have never worked in a packaged build.
v0.1.0 through v0.3.1 all ship it.

## Why nothing caught it

This is the third time in two days the same shape has appeared, and `SPEC-407` is the spec that
exists to prevent it:

*   `SPEC-407`'s checkpoints ask whether the sidecar is **present, real, the right architecture**,
    and — since `CTX-407.3` — **current**. All four were true. None of them asks whether it
    *works*.
*   Every test that exercises these agents runs **from source**, where `__file__` points at the
    real tree and the prompts are right there.
*   `CTX-407.3` Deviation 3 recorded that a module-level check passed while the frozen artifact was
    broken. `CTX-209.1` Deviation 2 recorded the same thing one layer out, with an SDK. This is the
    same lesson a third time, and the most expensive instance: **the daemon's own test suite cannot
    see this class of defect at all, because the defect only exists once the code is frozen.**

## 1. Feature Definition & Execution Plan

### Phase 1: Bundle the tree

*   [x] `datas=[(os.path.join(_HERE, "agentflow"), "agentflow")]` in `daemon.spec`.
*   [x] Bundled as data rather than adding a `sys._MEIPASS` branch to the three call sites. The
    runtime resolution is already correct; three branches would be three places to keep in sync
    with one that needs no branch at all.

### Phase 2: Make the absence detectable

*   [x] `TEST-019` fails if `datas` goes back to empty.
*   [x] `TEST-020` asserts the tree it names actually exists — a spec entry pointing at a missing
    directory would bundle nothing and fail identically, and silently.

### Not in this context

*   **A functional check of the frozen binary.** `SPEC-407`'s checkpoints are all static file
    inspection, which is why this survived them. A gate that actually *runs* the frozen sidecar and
    asserts a real route answers would have caught this, the stale sidecar in `CTX-407.3`, and the
    anthropic SDK break in `CTX-209.1`. That is a real addition to `SPEC-407` §2.2's checkpoint
    list and deserves its own context.

`test_ensure_sidecar.py`: 20 tests.

**Verified against the frozen artifact, which is the only place this defect exists.** Before: the
running app returned `Context directory not found: .../_MEI.../agentflow`. After re-freezing, the
same `component.search` request driven straight into the frozen binary over JSON-RPC got past agent
loading entirely and failed on *authentication* instead — the probe sent no API key. That error
progression is the proof: reaching the provider means the prompt tree was found and the agent
config loaded.

**Not verified.** `strings` on the binary shows nothing, because PyInstaller stores `datas`
compressed in its archive — the same reason `strings` was useless for route names in `CTX-407.3`
Deviation 2. And no human has yet run a real search through the rebuilt app.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1 — `SPEC-407`'s checkpoints cannot see this, and that is the finding.**
    *   The spec's stated goal is *"make it impossible for a local build to report success while
        producing an app that cannot work."* This build reported success and produced an app that
        could not work. Every check it defines — placeholder, architecture, and `CTX-407.3`'s
        currency — passed, because all three inspect the file rather than exercise it.
    *   *Impact:* the gap is structural, not an oversight in any one check. **Three separate
        defects in two days** — a stale sidecar, an SDK that removed a parameter, and now an
        unbundled data tree — were all invisible to static inspection and all obvious the moment
        the frozen binary was actually run. A checkpoint that spawns the sidecar and asserts a real
        route answers would have caught all three. Named here rather than built, because it changes
        `SPEC-407` §2.2's checkpoint model.

*   **Deviation 2 — the test suite is structurally incapable of catching this.**
    *   Every agent test imports from source, where `__file__` is the real tree. There is no
        arrangement of those tests that would fail on a missing `datas` entry, because the defect
        does not exist until PyInstaller runs.
    *   *Impact:* `TEST-019`/`TEST-020` assert the *spec file's* contents instead — a proxy, and an
        honest one, but only a proxy. They would not catch a `datas` entry that is present and
        wrong in some other way. The real check is Deviation 1's.
