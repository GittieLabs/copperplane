# CTX-213.1: Implementation Context: Local Models That Actually Work

> **Spec Reference:** Links to [SPEC-213](../specs/SPEC-213-local-models-that-work.md)

## 1. Feature Definition & Execution Plan

### Phase 1: Every route resolves through `provider_roles` (SPEC-213 §2.1)

*   [ ] `llm.chat` resolves through `llm_providers.resolve()` with `model_role="reasoning"`.
*   [ ] The agent-backed routes stop passing the legacy `llm_provider`/`llm_model` as an explicit
      override.
*   [ ] Provenance records the provider and model that were actually resolved.

### Phase 2: Setup errors say what is wrong (SPEC-213 §2.3)

*   [ ] `ModelSetupError`, raised by `resolve()` for a missing key, and by the capability gate.
*   [ ] `generate_component` raises it as itself and does not retry it.
*   [ ] `_explain_or_report_plainly` uses its message.

### Phase 3: A capable Ollama default (SPEC-213 §2.2)

*   [ ] Pull `qwen2.5:7b` (approved by the maintainer 2026-10-11), drive every agent class
      against it live, then move the preset's default and declare its capabilities.

### Phase 4: First-run setup and the requirements banner (SPEC-213 §2.4)

*   [ ] `llm_ready` in `daemon.get_capabilities`, consumed by `requirements.ts`.
*   [ ] An Ollama option in `GuidedSetup.tsx`, with three states: not running, model not pulled, ready.

### Phase 5: Frozen binary, the app window, docs

*   [ ] Re-freeze the sidecar and drive the CTX-408.9 Phase 7 matrix through it again.
*   [ ] Choose Ollama in first-run setup in the real app window, then get an explanation, a part
      lookup and a chat answer.
*   [ ] Update `install.md` and the v0.7.0 release notes' known-limits line.
