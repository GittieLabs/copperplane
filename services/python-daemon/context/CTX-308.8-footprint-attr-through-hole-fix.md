# CTX-308.8: Footprint Attr Through-Hole Fix

> **Spec Reference:** Links to [SPEC-308](../../../apps/tauri-ui/specs/SPEC-308-footprints-schematic-advisor.md)

## 1. Feature Definition & Execution Plan

A second, real bug found in the same real-footprint inspection that surfaced `CTX-108.2`'s row
spacing fix. `library_store._build_kicad_mod_text` (`CTX-308.6`'s own real export path) hardcoded
`(attr smd)` on every exported `.kicad_mod`, regardless of the footprint's own real pads --
confirmed directly in the generated ATtiny85 file: every pad is `thru_hole`, but the footprint itself
was tagged `smd`, a real, visible inconsistency the moment the file is opened in KiCad.

**Fix**: the function already computes `is_pth` per pad (`CTX-308.6`'s own existing logic); a real
`all_through_hole` check picks `(attr through_hole)` when every pad is really through-hole,
`(attr smd)` otherwise (unchanged for the existing all-SMD case, e.g. SOIC/TSSOP).

### Phase 1: `library_store.py`
*   [x] `_build_kicad_mod_text` computes `all_through_hole` and emits the real, correct `attr` line.

### Phase 2: tests
*   [x] `tests/test_library_store.py`: an all-SMD footprint asserts `(attr smd)`; an all-through-hole
    footprint asserts `(attr through_hole)` and explicitly not `(attr smd)`.

## Files
- `services/python-daemon/library_store.py` -- the real fix.
- `services/python-daemon/tests/test_library_store.py` -- new tests.

## Verification
- `services/python-daemon/.venv/bin/python3 -m unittest tests.test_library_store -v` -- 96/96
  passing, no regressions.
- Real `kicad-cli fp export svg` round-trip tests for both the all-SMD and all-through-hole path
  (`TestExportFootprintKicadMod.test_002`/`test_003`) already existed and were unaffected by this
  fix (they don't assert on the `attr` line, which is why this bug shipped unnoticed -- the file was
  still valid KiCad syntax, just semantically wrong).
