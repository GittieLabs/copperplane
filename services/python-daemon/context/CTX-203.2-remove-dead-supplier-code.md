# CTX-203.2: Implementation Context: Remove Dead Supplier-API Code

> **Spec Reference:** Links to [SPEC-203](../specs/SPEC-203-supplier-api-integration.md)

`SPEC-203` is now permanently retired (real vendor-terms/API-content research, 2026-08-18-19) --
distributor APIs don't return what this product needs and their terms structurally forbid what a
local-first CAD tool does. `CTX-203.1` had already shipped credential-independent plumbing for this
before that research happened: a "Supplier APIs" Settings UI section inviting a user to enter real
DigiKey/Mouser/Octopart credentials, four `KNOWN_SECRET_KEYS` entries, `get_capabilities` flags,
and a local pricing cache module. None of it was ever wired to a real HTTP client
(`CTX-203.1`'s own Plan Drift named this explicitly as deferred). Left in place, it would have kept
inviting a user to configure credentials for a feature that will now never exist -- real UI, doing
nothing, forever. Removed here rather than left as harmless-looking dead weight.

## 1. Feature Definition & Execution Plan

### Phase 1: Rust -- drop the four supplier secret keys
*   [x] `core/tauri-rust/src/daemon.rs`: `KNOWN_SECRET_KEYS` back down to the four real LLM
    provider keys; the doc comment above it no longer describes a "supplier keys" half that no
    longer exists.
*   [x] No other Rust code referenced these keys by name (`validate_known_key`/
    `collect_known_secrets`/`save_secret`/`clear_secret` are all generic over the allowlist) -- the
    existing Rust test suite already covers this without any test-specific removal needed.

### Phase 2: Python -- drop capability flags and the pricing cache module
*   [x] `daemon.py`: `_detect_capabilities()` no longer returns `digikey_available`/
    `mouser_available`/`octopart_available`.
*   [x] `library_store.py`: `save_supplier_pricing`/`load_supplier_pricing`/
    `_supplier_pricing_path`/`_supplier_pricing_dir`/`SUPPLIER_PRICING_REQUIRED_FIELDS` removed
    entirely, along with the module's own top-of-file layout comment describing the
    `supplier_pricing/` directory.
*   [x] Corresponding tests removed: `test_daemon.py`'s three capability-flag tests
    (`test_002d`-`test_002f`), `test_library_store.py`'s whole `TestSupplierPricingCache` class
    (six tests) plus its now-unused `datetime`/`timedelta`/`timezone` import.

### Phase 3: Frontend -- drop the Settings UI section
*   [x] `lib/settings.ts`: `SupplierField`/`SupplierDefinition`/`SUPPLIERS` and the three
    `*_available` fields on `DaemonCapabilities` removed.
*   [x] `Settings.tsx`: the `supplierKeyInputs`/`busySupplier` state, `handleSaveSupplier`/
    `handleClearSupplier` handlers, and the whole "Supplier APIs" `<section>` removed. The
    remaining "API Keys" (LLM providers) section is untouched.
*   [x] Corresponding tests removed: `Settings.test.tsx`'s whole "Settings: Supplier APIs"
    `describe` block (three tests); `settings.test.ts`'s `BASE_CAPABILITIES` mock no longer carries
    the three supplier fields.

### Phase 4: Historical record
*   [x] `CTX-203.1`'s own context file gets a "Superseded" note pointing here, rather than being
    silently deleted -- it's real history of what was tried and why, matching this repo's own
    "Plan Drift is not embarrassing" norm.
