# CTX-205.5: Structure Pass Heading Detection Fix

> **Spec Reference:** Links to [SPEC-205](../specs/SPEC-205-datasheet-design-guidance.md)

## 1. Feature Definition & Execution Plan

A real, serious bug found by the user's own live click-through of `CTX-205.4`'s just-shipped UI
against a **real** ATtiny85 datasheet, not `CTX-205.1`'s own small synthetic test fixture: clicking
"Generate Design Requirements" failed with `Extraction did not return valid JSON: Unterminated
string starting at: line 10 column 13`. `CTX-205.1`'s own structure pass -- "does this word appear
anywhere on this page" -- was never exercised against a real, large (234-page) technical reference
manual, where the same words this pipeline searches for (`reset`, `clock`, `oscillator`) appear
constantly in ordinary register/peripheral prose, not just the real dedicated sections.

**Real, measured severity, confirmed before designing a fix, not assumed:** ran the old
`locate_candidate_sections` against the real, user-provided `ATTINY85-20PU.pdf` (234 real pages) --
`reset` matched **84 of 234 pages**, `clock_oscillator` matched **141 of 234 pages**. Handing that
many real pages of text to a single LLM call for one category is both a real cost/latency problem
and the direct, confirmed cause of the reported crash: the model's response gets long enough to hit
`max_tokens` mid-string, producing invalid, truncated JSON.

**Real fix, verified against the real document, not just reasoned about:**
*   **Heading-based detection replaces whole-page keyword matching as the primary signal.** A real,
    numbered section-heading line (`8.2 Reset Sources` -- the real ATtiny85 style; `7. Absolute
    Maximum Ratings` -- this module's own synthetic fixture's style, and a real style other
    datasheets use too) is detected via `_HEADING_PATTERN`, anchored to the whole line so a Table of
    Contents' own real dotted-leader-plus-page-number lines (`4.8 Reset and Interrupt Handling
    ....... 12`) don't match -- confirmed against the real ATtiny85 ToC pages directly, not assumed.
    A category's real section then runs from its own detected heading's page up to (but not
    including) the next real heading found *anywhere* in the document (any category), capped at a
    new `_MAX_SECTION_PAGES = 4` -- a real, deliberate safety net against a pathologically long real
    section, not just a theoretical concern given what just broke.
*   **A real, genuine false positive found while building the fix itself, not invented**: real prose
    wrapped across a line boundary can itself start with a number ("...an external\n10 kOhm pull-up
    resistor to VCC should be added...") -- indistinguishable from a real heading number by line
    position alone. Every real heading found in the actual ATtiny85 document and this module's own
    fixture is a handful of words; this fake one ran to 13. Fixed with a real, simple
    `_MAX_HEADING_WORDS = 8` cap -- not a more elaborate Title-Case heuristic that would need its own
    tuning against real, varied datasheet formatting this session has no further evidence for yet.
*   **The old whole-page keyword search is kept as a real, honest fallback**, used only for a
    category with zero real heading matches anywhere -- a datasheet whose relevant section doesn't
    follow a numbered-heading convention this module can detect still gets *some* real coverage,
    still capped at `_MAX_SECTION_PAGES`, rather than silently returning nothing.
*   **`datasheet_guidance_extraction.prompt.md`'s `max_tokens` raised 2048 -> 4096** as a real,
    secondary safety margin -- even a correctly-bounded real section (up to 4 pages, potentially
    several real headings' worth for a category like `clock_oscillator`) can still contain enough
    real content to produce a long real cited-items response.
*   **Real, measured result against the same real document**: `reset` now matches 9 real pages (was
    84), `clock_oscillator` 18 (was 141) -- and the full real pipeline, run end-to-end against the
    real `ATTINY85-20PU.pdf` with a real Anthropic key, completed cleanly in ~57s with real, cited
    items for every category that had real content, no JSON errors.

**A second, unrelated real bug surfaced and fixed in the same live-testing session, worth recording
here since it blocked reaching this one**: the user's dev-mode daemon process invokes the bare
`python3` on their shell `PATH` (`~/.platformio/penv/bin/python3`, confirmed via `ps`/daemon log --
matches this repo's own documented "a debug build invokes python3 unchanged" behavior), which is a
**different interpreter** from `services/python-daemon/.venv` this whole `SPEC-205` arc had been
tested against all session. That interpreter had every other real dependency already installed
except `pdfplumber` (`CTX-205.1`'s own new addition), so `datasheet.generate_guidance` silently
failed to import and register (`daemon.py`'s own try/except-and-log-None pattern), surfacing as
`Method not found: datasheet.generate_guidance` in the real running app. Fixed by installing
`pdfplumber==0.11.10` directly into that real interpreter, matching `requirements.txt`'s own pin.
**Not a code change** -- a real, local-environment gap, named here for the record since it's exactly
the kind of thing "verify against the real thing" is supposed to catch and didn't, until a real user
hit it. No repo file encodes this fix; a fresh clone's own dev-mode `python3` could hit the same gap
again if it's ever missing a dependency `requirements.txt` gained after that interpreter was last
set up -- a real, standing risk this context does not attempt to solve (e.g. a startup dependency
check), named honestly as out of scope rather than silently left unmentioned.

### Phase 1: `datasheet_structure.py` -- real heading-based detection
*   [x] `_HEADING_PATTERN` -- a real, numbered-heading-line regex, matching both this module's own
    fixture's style and the real ATtiny85 datasheet's style, excluding Table-of-Contents lines.
*   [x] `_MAX_HEADING_WORDS` -- real false-positive guard against a wrapped line that starts with a
    number.
*   [x] `_MAX_SECTION_PAGES` -- real cap on how many pages a single detected section (or a
    no-heading-found fallback) can contribute.
*   [x] `_find_headings(pages) -> list[dict]` -- every real heading found anywhere, in page order.
*   [x] `locate_candidate_sections` rewritten: heading-based primary detection (section extends to
    the next real heading anywhere, capped), falling back to the original whole-page keyword search
    only when a category has zero real heading matches.
*   [x] `CATEGORY_PATTERNS`' own regexes reused unchanged -- now matched against real, short heading
    text instead of full-page prose, which is what they needed to be specific enough for all along.

### Phase 2: `agentflow/agents/datasheet_guidance_extraction.prompt.md`
*   [x] `max_tokens` raised 2048 -> 4096, a real secondary safety margin.

### Phase 3: tests
*   [x] `tests/test_datasheet_structure.py`: `test_009`/`test_010` tightened from `assertIn` to
    `assertEqual` now that cross-reference pollution is really gone; new `TestFindHeadings` (a real
    numbered heading is found; a ToC dotted-leader line is not; the real wrapped-line false positive
    is not; a heading exactly at the word cap still counts) and
    `TestLocateCandidateSectionsHeadingBased` (a section extends to but not past the next real
    heading; a section with no further heading is capped, not run to document end; a category with
    no real heading anywhere falls back to the real keyword search).
