# CTX-205.3: Datasheet Guidance Storage & Daemon Route

> **Spec Reference:** Links to [SPEC-205](../specs/SPEC-205-datasheet-design-guidance.md)

## 1. Feature Definition & Execution Plan

Wires `CTX-205.1`/`CTX-205.2`'s real pipeline into the real app: a new async daemon route
(`datasheet.generate_guidance`) that loads a real Part, ensures its datasheet is really cached
locally, runs the real extraction pipeline, and persists the result onto that Part's own record.
Class A (typed facts), Class C (general practice), and the UI panel remain real, deliberately
deferred scope.

**Real research performed before planning, not assumed:**
*   **A datasheet PDF is not guaranteed cached by the time a Part exists.** Read
    `library_save_confirmed_part` (`daemon.py`) in full: it never calls `cache_datasheet`.
    Caching only happens upstream, in the frontend's `ComponentDiscovery.tsx` (`handleConfirm`),
    explicitly best-effort and non-gating -- it can fail (a real vendor site behind bot
    protection was found blocking it) and there's no re-fetch anywhere in `PartDetail.tsx`. This
    route cannot assume a cached PDF exists; it must be prepared to fetch one.
*   **`cache_datasheet` always re-fetches unconditionally -- no existence check exists anywhere.**
    Confirmed by reading it in full. A regenerate-guidance action calling it directly would
    re-download the same real PDF over the network every single time. New
    `library_store.ensure_datasheet_cached(part_number, datasheet_url)` added specifically for
    this -- checks the real local path first, only calls `cache_datasheet` on a real cache miss.
    Duplicates (not shares) `cache_datasheet`'s own real path-safety guard, since raising before
    ever touching the filesystem (an existence check) is a genuinely different real code path from
    raising mid-fetch.
*   **The real Part schema-evolution convention is read-time backfill, not a `schema_version`
    bump.** Confirmed: every `save_*` function hardcodes `schema_version: 1`; there is no
    version-bump convention anywhere in this codebase. The one real precedent for adding an
    optional field to an already-shipped record shape is `_backfill_library_ids`
    (`record.setdefault(...)`, applied at every real `load_*` call site, never at save time).
    Mirrored exactly: new `_backfill_design_guidance` does `record.setdefault("design_guidance",
    None)` -- `None`, not `{}`, since SPEC-205 §5's own "silence must not be readable as 'no
    requirements'" principle means "never generated" and "generated, every category came back
    empty" must stay two real, distinguishable states.
*   **No existing precedent for a "list of cited items" provenance shape.** Confirmed by reading
    `_validate_part_provenance`/`PART_PROVENANCE_REQUIRED_FIELDS` in full -- every real provenance
    entry today is one flat `{"source": ...}` dict per required field, and `design_guidance` is
    genuinely optional (a category can legitimately be empty), so it is deliberately *not* added
    to that required-fields tuple, which would gate every real, unrelated Part save with no
    guidance yet. New `_validate_design_guidance` is a separate, lighter shape check, called from
    `save_part` only when the field is actually present.
*   **The real async-route pattern to copy exactly**: `kicad_generate_connection_guidance`
    (`daemon.py`) -- load the real Part via `library_store.load_part`, run a real LLM pipeline over
    it, thread `CONFIG.get("secrets")/("llm_provider")/("llm_model")` through, register
    conditionally in `_build_routes()`, add to `ASYNC_ROUTES`. This route does one real thing more:
    persists its result, rather than just returning it.
*   **Real `cancel_event` precedent exists only on the two FreeCAD routes** (confirmed by reading
    every real `cancel_event` usage in `daemon.py`/`freecad_bridge.py`) -- `kicad_generate_component`/
    `kicad_generate_connection_guidance` don't support it. Given a real 8-category document takes
    ~20-30s+ (`CTX-205.2`'s own observed timing, and the real end-to-end test for this context took
    ~33s including two real category re-tries after transient `400`s), added real, coarse-grained
    cancellation to `datasheet_guidance.generate_datasheet_guidance`/`_run_all_categories_and_close`:
    checked once per category, before that category's own workflow starts -- not mid-LLM-call, but
    real, matching the exact `cancel_event is not None and cancel_event.is_set()` check
    `freecad_bridge._wait_with_cancellation` already uses. `daemon.py`'s own `_run_job` already
    passes `cancel_event` to any route function whose real signature declares the param (via
    `inspect.signature`) -- no new per-route opt-in mechanism needed.
*   **No content-hashing precedent exists on `develop`.** Confirmed by grep -- genuinely new code,
    a plain `hashlib.sha256(file_bytes).hexdigest()`, not a reuse of anything. `document_revision`
    (a real, human-readable string like "Rev. C") is deliberately left `None` -- honest, unbuilt
    scope, not a fabricated placeholder: no extraction step for it exists yet.

**Real, live, end-to-end verification, not just reasoned about**: dispatched
`datasheet.generate_guidance` through `handle_request` exactly as a real client would, against a
real local HTTP server serving `CTX-205.1`'s own fixture PDF, with a real Anthropic API key --
confirmed `job.completed` with the real, cited, persisted guidance on the real Part record.

## 4. Plan Drift & Architectural Changes
*Document any deviations from the original SPEC definitions encountered during build time.*

*   **Deviation 1: the mocked route test in `test_daemon.py` calls the route function directly,
    not through `handle_request`, discovered by a real, failing first attempt.** The original plan
    (implicit in mirroring `TestLibraryRoutes`'s own `_dispatch` helper) assumed dispatching through
    `handle_request` and asserting synchronously afterward would work. It doesn't: registering the
    route in `ASYNC_ROUTES` (a deliberate, correct design choice, not itself the mistake) means
    `handle_request` returns a `job_id` immediately and runs the real work on a background thread
    -- a synchronous post-dispatch assertion races that thread and fails (confirmed by a real test
    run: `mock_ensure_cached` showed 0 calls). Fixed by calling `daemon.datasheet_generate_guidance(...)`
    directly for the orchestration-logic test, and writing a separate, real, `handle_request`-based
    end-to-end test in `test_async_jobs.py` (this repo's own established home for that class of
    test, mirroring `TestRealComponentGenerationJob` exactly) to prove the full async chain for
    real. *Impact:* better test organization than the original plan, not just a fix -- the
    orchestration logic and the async-job-wrapping mechanics are now each tested in the file
    already scoped for that concern, matching this repo's own existing convention rather than
    inventing a new one.
