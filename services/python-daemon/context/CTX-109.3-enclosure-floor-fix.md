# CTX-109.3: Enclosure floor fix: found by live user testing, not this module's own tests

> **Spec Reference:** Links to [SPEC-109](../specs/SPEC-109-parametric-enclosure-generator.md)

The exact real click-through verification `CTX-109.2`'s own Plan Drift named as not performed (no
screen-control tool was available in that session) is what caught this: the user generated a
board-driven enclosure for real and reported *"a 'wrapper' with fillet sides... no top or bottom"*.
`freecad_bridge.py`'s hollow-shell script cut the inner cavity the *full* height starting at
`z=0`, identical to the outer box's own height -- producing an open-both-ends tube, not an
enclosure. `CTX-109.1`'s own real, no-mocks geometry verification (prototyped against `freecadcmd`,
exact volume assertions) never caught this because it verified the shell/standoff/fillet math was
internally consistent, not that the *design itself* matched what a real enclosure needs -- a real
gap between "the geometry is what the code says" and "the geometry is what a person actually wants."

## 1. Feature Definition & Execution Plan

### Phase 1: A real solid floor, open top
*   [x] The inner cutout now starts at `z = wall_thickness_mm` (not `z = 0`) and is
    `height - wall_thickness_mm` tall (not the full `height`) -- leaving a solid floor slab at the
    bottom, thick as the walls, and an open top. This is the standard 3D-printable tray design
    (SPEC-109 §1's own non-goals already rule out lid/fastener hardware, so an open top is the
    correct scope, not a shortfall) -- not a lidded box, and not the open-both-ends tube the bug
    produced.
*   [x] Standoff cylinders are unchanged (still start at `z=0`) -- they were always meant to fuse
    into the floor from below, and now that a real floor exists there, the fuse is physically
    correct instead of merging into empty space.

## 4. Plan Drift & Architectural Changes

**This bug was found only because the user did the exact verification `CTX-109.2` had explicitly
flagged as not performed.** `CTX-109.1`'s real, no-mocks geometry tests (prototyped directly against
`freecadcmd`, exact-volume assertions) verified the shell/cavity/standoff/fillet math was internally
self-consistent -- and it was, consistently producing an open-both-ends tube, because that's what the
code actually specified. Automated geometry tests can confirm code does what it says; they cannot
substitute for a person looking at the result and recognizing it doesn't hold a circuit board. This
is recorded here as direct, concrete evidence for why `CTX-109.2`'s Plan Drift treated the missing
native-window click-through as a real gap rather than a formality -- it was.

**A `mesh.contains()`-based point-in-solid regression test was attempted and dropped.**
`trimesh`'s `.contains()` needs the optional `rtree` package, which isn't installed in this
environment, and adding a new dependency for one test's convenience wasn't judged worth it. The
existing exact-volume assertions in `test_001`/`test_002` already discriminate the bug
unambiguously -- the old (buggy) shell volume was `1640`, the corrected one is `2312`, a 41%
difference, both computed from real geometry against a real `freecadcmd` run -- so no dedicated new
test was added; the two existing tests' corrected expected values *are* the regression coverage.
