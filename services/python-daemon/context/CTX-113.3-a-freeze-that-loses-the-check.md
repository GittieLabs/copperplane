# CTX-113.3: Implementation Context: A Freeze That Loses the Check

> **Spec Reference:** Links to [SPEC-113](../specs/SPEC-113-structural-consistency-checks.md)

The maintainer rebuilt the app and the symbol/footprint findings were gone. The cause was mundane
-- their working tree was on a branch without the code, because I put it there -- but chasing it
found a real hole in the one guard that is supposed to make this class of failure impossible.

## 1. Feature Definition & Execution Plan

### Phase 1: the immediate cause
*   [x] Moving three loose spec files onto their own branch meant checking out a branch off
    `develop`, which swapped the working tree off `SPEC-113`'s code. The next build re-froze the
    sidecar from a source tree that had no `structural_checks.py`, so the app genuinely lost the
    feature. Entirely my doing.
*   [x] Working tree returned to the branch that carries it, and the sidecar re-frozen.

### Phase 2: the hole that made it worth more than an apology
*   [x] `structural_checks` is an optional import **inside** `chat_agents`, guarded by a bare
    `try/except` that sets it to `None`. A freeze that missed the module would leave `chat.review`
    answering perfectly normally and reporting only what ERC and DRC already said.
*   [x] `ensure_sidecar` verifies the binary is present, real, current, the right architecture, and
    answers all 81 routes with no degraded modules. **None of those would have failed.** Every
    route is still there; only the findings are gone.
*   [x] That is the shape `CTX-407.3` and `CTX-407.4` both shipped in, and the rule CLAUDE.md
    states directly: a check that cannot fail is not evidence, even when its conclusion is right.

### Phase 3: make the artifact answerable
*   [x] `daemon.py` now checks `chat_agents.structural_checks` after importing `chat_agents` and
    records a degraded module when it is missing, so `daemon.ready` and `daemon.list_routes` carry
    it.
*   [x] Asked the frozen binary over JSON-RPC rather than trusting the freeze: 81 routes,
    `degraded_modules: none`, `chat.review` present.

## 4. Plan Drift & Architectural Changes

**1. I broke the maintainer's build, again, by moving their working tree.** Putting the loose spec
files on their own branch required checking out a branch off `develop`. That is correct for the
files and careless about the tree those files were sitting in: the app they had just been testing
lost a feature because of a housekeeping commit. The lesson is not "do not branch" -- it is that
switching a branch under someone who is actively building is a change to their environment, and
should be said out loud at the time, not discovered by them afterwards.

**2. The guard that exists for exactly this could not have caught it.** `SPEC-407` was written
because a sidecar shipped "with the entire AI surface disabled" while looking healthy, and its
answer -- ask the running artifact what it can do -- is right. But it asks for routes, and this
failure removes no route. `chat.review` answers; it just stops finding anything. An optional import
nested inside another module is invisible to a route list, and every new one is a new blind spot
unless it is registered.

**3. Not verified: a freeze that has actually lost the module.** The guard is asserted against the
condition `daemon.py` evaluates, and the real import is asserted to have succeeded, and the frozen
binary was asked and answered. What has not been done is deliberately building a sidecar without
`structural_checks.py` and watching `ensure_sidecar` refuse it. That is the only test that proves
the whole chain, and it costs a four-minute freeze; it is worth doing once before the next release
rather than assuming.

**4. CI caught the half of this I had not done.** Registering `structural_checks` as a degradable
module is only half the job: `test_ui_route_parity` requires every such module to have a
plain-language description in the UI, because the notice falls back to naming an unknown module as
itself. A user whose freeze had lost these checks would have been shown the bare word
`structural_checks` at the moment they were most confused. The guard fired on all three runners and
named it, which is exactly what it is for -- and it is worth noticing that the fix I wrote for one
blind spot immediately created another one, in the layer above.
