# CTX-102.1: Python JSON-RPC Daemon Sidecar

> **Spec Reference:** Links to [SPEC-000](../../../specs/SPEC-000-architecture-overview.md)

## 1. Feature Definition & Execution Plan
This feature implements the persistent background Python process that listens to Tauri via standard input, executes mapped commands, and replies via standard output.

### Phase 1: Foundation & Stdin Loop
*   [ ] Set up `services/python-daemon/daemon.py`.
*   [ ] Implement the `sys.stdin` infinite reading loop.
*   [ ] Ensure `sys.stdout.flush()` is called after every write to prevent pipeline buffering issues.

### Phase 2: JSON-RPC 2.0 Parsing & Error Handling
*   [ ] Parse incoming strings as JSON.
*   [ ] Extract `jsonrpc`, `method`, `params`, and `id` fields.
*   [ ] Return standardized error payloads (e.g., `-32700 Parse error`, `-32601 Method not found`) if the input is malformed or the method doesn't exist.

### Phase 3: Route Dispatcher & Mocking
*   [ ] Create a routing dictionary mapping string methods to Python functions.
*   [ ] Implement a mock method `kicad.generate_component` that accepts a `query`, sleeps for 1.5 seconds, and returns a success payload (to test end-to-end Tauri integration later).
