# CTX-205.2: Datasheet Guidance Extraction (Class B)

> **Spec Reference:** Links to [SPEC-205](../specs/SPEC-205-datasheet-design-guidance.md)

## 1. Feature Definition & Execution Plan

Builds on `CTX-205.1`'s real structure pass with the first real extraction class: **Class B**
(cited datasheet prose, SPEC-205 §2.1) via a real AgentFlow `.workflow.md` DAG. For a real
category with at least one candidate page, an LLM extracts cited guidance items; a deterministic
handler then validates every item's citation against the real document before it's trusted. Class
A (typed tabular facts), Class C (labelled general practice), the new async daemon route,
Part-record storage, and the UI panel remain real, deliberately deferred scope -- named honestly
below, not silently skipped.

**Real research performed before planning, not assumed:**
*   **The real AgentFlow DAG shape**, read directly from `component_pipeline.py`'s own
    `generate_component`/`component_intelligence.workflow.md` (`extract` agent node ->
    `validate` handler node, `ConfigLoader` -> `WorkflowExecutor` -> `asyncio.run`, provider
    clients tracked in a list and closed in one shared `finally` to avoid the real, already-fixed
    leak `_build_agent_executor`'s own docstring documents). This context's own DAG
    (`agentflow/workflows/datasheet_guidance.workflow.md`) mirrors that shape exactly.
*   **A real AgentFlow constraint, found by reading the vendored source directly (`workflow/
    executor.py`/`workflow/node.py`), not assumed**: a handler node only ever receives *prior node
    outputs* -- there is no mechanism for a downstream handler to see the workflow's own
    `initial_message` once execution has moved past the entry node (`__initial__` is only injected
    for a true entry node with empty prior outputs, and is never written back into the outputs dict
    later nodes see). Citation validation here genuinely needs the real page texts -- external
    data, not a node's own output -- to check a quote actually appears where it's cited. Resolved
    with a closure: `_make_validate_handler` builds a fresh `validate` handler per real call, bound
    to that call's real page texts via Python closure, not AgentFlow's own node-output wiring. The
    DAG structure and execution stay 100% real AgentFlow; only the handler's own captured inputs
    are plain Python -- exactly as legitimate as `component_pipeline.py`'s own inline
    `runner_factory` closures already are, and confirmed working by a real end-to-end run (below),
    not just reasoned about.
*   **`_build_agent_executor` is imported from `component_pipeline`, not duplicated.** Real,
    already-tested logic (provider override precedence, the leak-fix client-tracking contract) --
    duplicating it risks drift if that logic changes in one copy and not the other. `_extract_json`
    *is* duplicated (a much smaller, self-contained utility) to keep this module's own JSON-parsing
    independent of SPEC-202's pipeline module, matching this repo's established per-feature-module
    independence (`kicad_bridge`/`freecad_bridge`/`component_pipeline` don't cross-import each
    other either) -- a real, deliberate asymmetry, not an oversight.

**Real design decision: items are filtered, not fatal.** SPEC-205 §2.2 states explicitly: "An item
that loses its citation during assembly is dropped, not promoted." Implemented literally --
`validate_datasheet_guidance` silently drops any item whose `page` isn't one of the real candidate
pages this category was given, or whose `quote` doesn't actually appear (whitespace-normalized,
case-insensitive substring match) on that page's real text -- never raises for an individual bad
item. A genuinely unparseable extraction response (not real JSON at all) *does* raise
`DatasheetGuidanceError`, a different, real failure mode from "some items didn't validate."

**Real design decision: one workflow run per category, sequential, and a real zero-cost
short-circuit for categories with no candidates.** A category with zero candidate pages
(`CTX-205.1`'s own structure pass result) never reaches the LLM at all -- matching
`component_pipeline.explain_violations`'s own "empty input, no LLM call" precedent, real cost
avoided, not just latency. Categories that do run are run sequentially, not concurrently -- a real,
deliberate simplification for this context, not yet proven to need concurrency; a genuine future
optimization if real multi-category latency proves too slow, not attempted here.

**Real, live verification, not just reasoned about**: ran the real DAG against `CTX-205.1`'s own
real fixture PDF, both for a single category and for all 8 real categories together (~23s total,
sequential, real Anthropic calls) -- every category returned real, correctly-cited items (e.g.
"reset" found real quotes on pages 2, 5, and 8, matching `CTX-205.1`'s own structure-pass findings
for that exact category exactly).

*   [x] New `agentflow/agents/datasheet_guidance_extraction.prompt.md` -- given a category name and

    correct answer.
*   [x] New `agentflow/workflows/datasheet_guidance.workflow.md` -- the real `extract -> validate`
    DAG, mirroring `component_intelligence.workflow.md`'s own exact shape.

*   [x] `DatasheetGuidanceError` -- a real, unparseable extraction response fails closed.

    real, pure helpers.
*   [x] `_make_validate_handler(pages_by_number, category, page_numbers)` -- the closure-based
    handler builder described above.
*   [x] `_run_category_workflow`/`_run_all_categories_and_close` -- runs the real DAG once per real

    matching SPEC-205 §5's own "first-class empty state" principle even at this backend layer).
