# CTX-206.4: Implementation Context: Source Reference Validation Model

> **Spec Reference:** Links to [SPEC-206](../specs/SPEC-206-agent-context-store.md)

**Scope note:** the fourth slice of `SPEC-206`, scoped to §2.3's `SourceRef` validation model. Six of
the eight real `SourceRef` kinds get a real resolver against already-persisted state
(`datasheet_page`, `guidance_item`, `connection_guidance`, `part_field`, `chat_turn`,
`project_intent`); two (`check_finding`, `note`) are named, deliberate gaps -- neither has real
backing state yet (ERC/DRC results are never persisted with a stable id; `chat.promote_turn`/§2.7
hasn't shipped). New module `services/python-daemon/chat_agents.py`, per `SPEC-206` §2.8's own module
map -- the first real content in a module otherwise reserved for the router/agent layer (§2.5),
which is real, separate, later work.

## 1. Feature Definition & Execution Plan

### Phase 1: A pure datasheet-cache path helper (`library_store.py`)
*   [x] `datasheet_cache_path(part_number)` -- the deterministic local cache path, no filesystem
    check, no network; refactored `cache_datasheet`/`ensure_datasheet_cached`'s own duplicate path
    construction to call it too, rather than adding a third copy.

### Phase 2: Resolvers (`chat_agents.py`)
*   [x] `_resolve_datasheet_page` -- a `content_hash` match against the real cached file is the whole
    check. Deliberately does **not** re-open/re-parse the PDF to verify `page` is within a real page
    range -- the citation-time validator already checked that when the reference was first created,
    and a hash match proves the file is byte-identical to what was cited then, so whatever was true
    about its pages then is still true now.
*   [x] `_resolve_guidance_item` -- part exists, `design_guidance.content_hash` matches, the category
    and quote are really present among that category's items.
*   [x] `_resolve_connection_guidance` -- part exists, `connection_guidance` exists, the pin number is
    really among its `pin_guidance` entries. No `content_hash` on this kind at all, matching
    `SPEC-206` §2.3's own union exactly -- this kind carries no staleness signal by design.
*   [x] `_resolve_part_field` -- part exists, `field` is a real top-level key on it.
*   [x] `_resolve_chat_turn` -- `library_store.load_thread(scope, scope_id)` (built in `CTX-206.3`)
    really contains a turn with that `turn_id`.
*   [x] `_resolve_project_intent` -- project exists and its `intent` is truthy (an unset `None` or an
    explicitly-cleared `""` both correctly fail to resolve -- there is nothing to cite either way).
*   [x] `_resolve_deferred` -- wired for `check_finding` and `note`, always `False`, named explicitly
    in the module's own docstring rather than silently omitted from the dispatch table.
*   [x] `resolve_source_ref(ref)` / `validate_source_refs(refs)` -- the two public entry points;
    the latter is exactly `sources`/`sources_dropped` from `SPEC-206` §2.2's turn shape, ready for
    `chat.send` (§2.5) to call once it exists.

### Phase 3: Tests
*   [x] `tests/test_chat_agents.py` (new, 28 tests) -- every resolver's real-resolves and
    real-does-not-resolve cases, both deferred kinds, malformed/unknown-kind/non-dict input, and
    `validate_source_refs`'s split-and-count behavior. Real file I/O against a real, isolated temp
    storage root (`ChatAgentsTestCase`, mirroring `test_library_store.py`'s own
    `LibraryStoreTestCase`) -- no mocking of `library_store` itself, since these are exactly the
    records it already persists for real.
*   [x] Full suite: `python3 -m unittest discover tests` -- **552 passed, 6 skipped**, 0 failures.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1 (non-deviation, confirmed as designed): `check_finding` and `note` are wired into
    the resolver dispatch table as an always-`False` function, not omitted from it.**
    *   *Reasoning:* `SPEC-206` §2.3 names all eight kinds as real; silently leaving two out of the
        dispatch table would make `resolve_source_ref` raise or behave inconsistently for a
        well-formed ref of either kind, rather than following the spec's own contract that an
        unresolvable reference is dropped, not repaired. Wiring both explicitly, with the reasoning
        in the module's own docstring, keeps the eight-kind union complete and makes the real gap a
        documented, deliberate fact instead of a silent omission a future reader would have to
        rediscover by grepping for a `KeyError`.
    *   *Impact:* None today (no caller exists yet); a real resolver for either kind is a pure
        addition to `_RESOLVERS` once its backing state exists (`SPEC-206` §2.5's live tool-call
        results for `check_finding`, §2.7's promoted notes for `note`).
*   **Deviation 2 (non-deviation, confirmed as designed): `_resolve_datasheet_page` does not verify
    `page` against a real page count.**
    *   *Reasoning:* Explained directly in the resolver's own docstring -- the citation-time
        validator (`datasheet_guidance._make_validate_handler`) already proved the page was real
        when the reference was first created; a `content_hash` match here proves the file has not
        changed since, so re-deriving the page count (which would mean opening and parsing the PDF
        with `pdfplumber` on every single resolution check, a real, avoidable cost on a potentially
        200+ page document) adds no correctness this check doesn't already have another way.
    *   *Impact:* None on correctness, real savings on cost -- confirmed the resolver never imports
        or calls `datasheet_structure.extract_pages` at all.
