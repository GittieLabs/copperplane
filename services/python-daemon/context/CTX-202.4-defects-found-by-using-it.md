# CTX-202.4: Implementation Context: Six Defects Found by Using the Built App

> **Spec Reference:** Links to [SPEC-202](../specs/SPEC-202-component-intelligence-pipeline.md)

The maintainer opened the built app to take documentation screenshots and, over about half an hour,
photographed six defects. Every one of them was invisible to a suite of 1,126 daemon tests and 825
frontend tests. None of them needed a debugger; all of them needed somebody to click.

**Scope note, stated plainly:** four of these live in `SPEC-202`'s pipeline; two do not -- the rail
on the onboarding surface is `SPEC-336`, and the provenance and enclosure messages belong to
`SPEC-300`'s storage rules. They are in one context because they were found in one pass and share
one cause. Splitting them across four branches would have cost more than it clarified.

## 1. Feature Definition & Execution Plan

### Phase 1: the package reference table, for the third and fourth time
*   [x] `QFN-32` (an ATmega16U2-MU) and then `QFN-48` (an ESP32-D0WDQ6) both failed closed against
    a 16-entry table. `CTX-202.2` added `QFN-56` for exactly this reason, and a `PDIP-N` alias
    exists for the same class of miss. That is four separate occasions.
*   [x] Both added, using the same `0.40-0.60` pitch range as every sibling QFN entry, and
    deliberately **not** marked `exposed_pad` -- the datasheets were not consulted, and guessing
    there widens a safety check.

### Phase 2: extraction ran out of room
*   [x] `ESP32-D0WDQ6` failed with "no JSON value found". Measured rather than guessed: the raw
    response was 2481 characters, ended mid-object at `{"number":` on pin 31 of 48, with 33 open
    braces against 31 closes. The model hit `max_tokens: 2048` and stopped.
*   [x] Raised to 8192, matching the chat agents. `max_tokens` is a ceiling, not a spend. Verified
    on the same part: the response came back complete and balanced at 3953 characters.
*   [x] An unclosed brace now produces "the model's answer was cut off before it finished" instead
    of 500 characters of raw JSON in a red box. The payload moved to the log, where its reader is.

### Phase 3: the symbol was unreadable
*   [x] `_KICAD_SYM_HALF_WIDTH_MM` was a fixed 5.08mm whatever the pins were called. KiCad draws a
    pin name inward from the body edge, so on a real ATTINY85 `PB0/MOSI/DI/SDA/AIN0/OC0A` ran
    across the centreline into `PB5/RESET/ADC0/dW` coming the other way.
*   [x] The body is now sized from the longest name on each side, rounded up to KiCad's own 2.54mm
    grid, with the old 5.08mm kept as a floor. That ATTINY85 goes from 5.08mm to 22.86mm; a part
    whose pins are all called `GND` is unchanged.

### Phase 4: error messages written for the wrong reader
*   [x] Four messages cited things a user cannot see: `PACKAGE_REFERENCE`, `SPEC-300 §2.2`,
    `CTX-308.5`, and `SPEC-304` plus `ROADMAP.md §3.3`. All four rewritten to say what was not
    done, what still works, and what to try.
*   [x] `tests/test_user_facing_errors.py` walks the AST of every module that raises through the
    JSON-RPC boundary and fails on a spec number, a context number, a section mark or a
    SCREAMING_CASE identifier inside a raised message. It reads only raised strings, so the same
    reference in a comment or docstring is left alone.

### Phase 5: the rail during onboarding
*   [x] First launch showed the projects rail, the library count and Settings beside "Welcome to
    Copperplane" -- offering a way around the question the screen is asking, and telling someone
    who has never opened the app that they are already inside it.
*   [x] Hidden on both onboarding surfaces, using the condition `RequirementsBanner` already had
    and the Rail never got. Extracted to one named value so they cannot drift apart.

## 4. Plan Drift & Architectural Changes

**1. The guard found a defect the maintainer had not.** `test_user_facing_errors.py` was written to
pin the three messages that had been photographed. On its first run it failed on a fourth --
`library_store.py:1440`, an enclosure message citing `SPEC-304` and `ROADMAP.md §3.3`. Nobody had
reached that path in the app yet. That is the difference between fixing three bugs and fixing a
class.

**2. The closed package table is the real problem and this does not fix it.** Adding `QFN-32` and
`QFN-48` is the fourth patch to a 16-entry exact-string table. Two of the three failures
photographed today were not packages at all: `Arduino Uno R3 Module` and `SMD Module (Castellated
38-pin)` are descriptions of modules, and no table of package geometries will ever contain them.
`SPEC-202 §3` chose to fail closed deliberately and that choice is not mine to reverse in a bug
fix, so it stands -- but a maker adding an Arduino shield currently gets a red error for a part
that is fine. **This needs a product decision** and is written up as such rather than quietly
loosened.

**3. Truncation had been considered and ruled out before, on weaker evidence.** `CTX-202.2` records
"three fresh, direct calls to the real extraction agent all succeeded well under max_tokens, ruling
out truncation-at-the-limit as the cause". That was true of the part being tested then and became
false as soon as a 48-pin part arrived. Counting braces in the actual failing response took under a
minute and settled it; three successful calls with a different part never could have.

**4. Not fixed, and not reproducible from here: the datasheet 403.** An `ATmega16U2-MU` datasheet
fetch returned HTTP 403. The obvious suspect was the `User-Agent` (`copperplane/0.1`), and it is
wrong: the Microchip URL available here returns 200 with that agent, with a browser agent, and with
none at all. The failing URL was never saved, because the fetch that would have saved it failed.
Needs the real URL before anything is changed.

**5. Still open, and raised rather than built: reporting a problem from inside the app.** The
maintainer asked for a way to log an issue and offer a GitHub link, rather than requiring a person
to open GitHub themselves. That is a new user-facing surface and wants its own spec, not an
appendix to a bug-fix branch.
