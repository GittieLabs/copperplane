# CTX-402.11: Implementation Context: The Install Window, Measured

> **Spec Reference:** Links to [SPEC-402](../../../specs/SPEC-402-release-signing-and-auto-update.md)

`CTX-402.10` shipped a branded install window that nobody opened. The maintainer opened it and it
was wrong in two ways at once: a horizontal scroll bar, and no text of any kind.

## 1. Feature Definition & Execution Plan

### Phase 1: measure what Finder actually does
*   [x] Finder sizes a DMG background from the image's **DPI**, not from the window. Points equal
    pixels divided by DPI over 72. The shipped PNG was 1320x800 at the default 72 DPI, which is
    1320x800 *points* -- exactly twice the 660x400 window. Hence the scroll bar, and hence every
    drawn element sitting at twice its intended distance from the icon it pointed at.
*   [x] Confirmed against the framework Finder itself uses rather than by reasoning about it:
    `NSImage(contentsOfFile:).size` reports `1320.0x800.0` for the asset that shipped and
    `660.0x400.0` for the replacement.

### Phase 2: fix the sizing
*   [x] The generator now writes the PNG's `pHYs` chunk at 144 DPI, so the same 1320x800 pixels
    measure 660x400 points and stay crisp on a retina display. The chunk is written by the script,
    not by whoever runs the render -- the previous instructions left it to a manual `rsvg-convert`
    command that had no way to set it.

### Phase 3: put words on it
*   [x] The wordmark, read straight out of `svg/wordmark-on-dark.svg`, which is already outlined.
    This is why the generator still needs no fontTools.
*   [x] An instruction line under the icons: "Drag Copperplane into your Applications folder."
    Body copy, set in the system sans, never the wordmark.
*   [x] Both sit outside the 74px clear radius around each icon, so nothing lands under an icon or
    its filename.

### Phase 4: one command
*   [x] `python3 tools/dmg_background.py` now writes the SVG, renders the PNG, sets the DPI, and
    copies it into `core/tauri-rust/dmg/`. It refuses to run without `rsvg-convert` rather than
    quietly producing artwork with every stroke missing.

## 4. Plan Drift & Architectural Changes

**1. "Rendered at 2x and Finder scales it down" was an invention, and I wrote it into four places.**
It went into the config comment, the generator's docstring, the brand README, `CTX-402.10`'s Plan
Drift, and a passing test named
`test_503_the_background_is_drawn_at_twice_the_window_size`. Every one of those restated the belief;
none of them measured anything. The mechanism is DPI, and the correct sentence is that Finder
divides pixels by DPI over 72.

**2. The test I wrote asserted the pixel size, which was never in doubt.** It read the PNG header,
compared it to `(1320, 800)`, and passed -- on a file that was twice the size of its window. It
would have passed just as happily on the broken asset forever, because the number it checked was
the number I had chosen and the number that mattered was one I had not thought to compute. This is
CLAUDE.md's rule about a check that cannot fail, arriving from a new direction: the check *could*
fail, it just could not fail *for the actual defect*. The replacement was run against the shipped
file and does fail on it.

**3. The reason it shipped at all is written in the previous context: "Not verified: what it looks
like when a person opens it."** I recorded the gap accurately, called it a thirty-second check,
and opened a PR anyway. Both defects were visible in the first second of that check. Naming an
unverified thing is not the same as verifying it, and a gap I can close in thirty seconds is not a
caveat -- it is work I skipped.

**4. There was no branding text at all, and I did not notice.** The drawing had a mark and an
arrow. The kit's wordmark was sitting outlined in `svg/wordmark-on-dark.svg` the entire time,
needing no fontTools, and the docstring I wrote said "this needs no text at all" as though that
were a design decision rather than a consequence of not having looked.

**5. Not fixed, and out of our control: hidden files.** With Finder set to show hidden files the
volume also shows `.background` and `.VolumeIcon.icns`, unpositioned and overlapping each other.
Tauri's bundler does not place them and exposes no option to. Most people never see them; the
maintainer does, because their Finder is set that way.
