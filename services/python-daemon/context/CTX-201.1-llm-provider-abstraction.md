# CTX-201.1: LLM Provider Abstraction

> **Spec Reference:** Links to [SPEC-201](../specs/SPEC-201-llm-provider-abstraction.md)

**Scope note:** implements real, verified support for five provider configurations — Anthropic,
Google, Perplexity, and Ollama, each verified for real against a live API/local server; OpenAI's
code path exists (it's the same `OpenAICompatProvider` mechanism as Perplexity/Ollama, just pointed
at the real default endpoint) but was **not verified for real in this session** — no real API key
was available (see Plan Drift). Session/workflow state and the `agentflow/` config tree
(`SPEC-201` §2's other decisions) stay out of scope, per that spec's own non-goals.

## 1. Feature Definition & Execution Plan

### Phase 1: Provider wrapper module
*   [x] `services/python-daemon/llm_providers.py`: `_build_provider` (lazy-imports the matching
    AgentFlow class per provider name — never at daemon startup) and `chat` (the sync/async
    boundary, via `asyncio.run`, since `daemon.py`'s `ROUTES` dispatch is synchronous).
*   [x] `requirements.txt`: `gittielabs-agentflow[anthropic,openai,google]==0.8.1` — the three
    provider SDK extras actually needed, not `[all]` (which also pulls in vector stores, S3,
    telemetry this spec has no use for).

### Phase 2: Wire `CONFIG["llm_provider"]`/`["llm_model"]` — closing a real gap
*   [x] `daemon.py`'s `_apply_env_config` never read `llm_provider`/`llm_model` from the env-injected
    config, even though `CTX-106.1` added both fields to Rust's `DaemonConfig` in anticipation of
    this spec. Fixed: both now populate `CONFIG`.

### Phase 3: The `llm.chat` route
*   [x] `daemon.py`: `llm_chat` resolves provider/model from `CONFIG` (or an explicit override) and
    the matching secret (`CONFIG["secrets"][f"{provider}_api_key"]`), then calls
    `llm_providers.chat`. Registered as an **async route** (`SPEC-105`) — a real LLM call is almost
    always multi-second, same reasoning as `freecad.generate_enclosure`.
*   [x] `core/tauri-rust/src/daemon.rs`: `KNOWN_SECRET_KEYS` (empty since `CTX-106.1`) gains
    `anthropic_api_key`, `google_api_key`, `openai_api_key`, `perplexity_api_key` — this is the
    context `CTX-106.1`'s own comment named as "the first spec with a real key to add here."

### Phase 4: Real per-provider model defaults — not AgentFlow's own
*   [x] Verified each provider's default model for real before trusting it. Found and fixed a real
    bug: AgentFlow's `GoogleGenAIProvider` default (`gemini-2.5-flash-preview`) 404s — confirmed via
    Google's own live model-list endpoint that it no longer exists. `llm_providers.py` sets its own
    `_DEFAULT_MODELS`, verified against each provider's real, currently-available models.

### Phase 5: Fix a real resource leak the first real test run surfaced
*   [x] The first real call to each provider left an `AsyncOpenAI`/`AsyncAnthropic`/`genai.Client`
    connection open when `asyncio.run()` tore down its event loop, producing a real (if harmless)
    `RuntimeError: Event loop is closed` on cleanup. Fixed: `_close_provider_client` closes the
    underlying SDK client from *inside* the same event loop, before `asyncio.run()` returns.

### Phase 6: Testing — real, per the local `.env.local` credentials made available this session
*   [x] Mocked/local: `_build_provider` constructs the right class with the right `base_url` for
    each provider name; an unknown provider name raises a clean error.
*   [x] **Real**, skipping cleanly when its own credential/local-server isn't available: Anthropic,
    Google, Perplexity all called for real via keys loaded from the repo root's `.env.local` (a
    test-only convenience — parsed directly by the test file, never touching production code, which
    still only ever reads secrets from `CONFIG["secrets"]` per `SPEC-106`); Ollama called for real
    against the actually-running local server (model `llama3.2:1b`, pulled this session).
*   [x] A full end-to-end test: `llm.chat` submitted through `handle_request` exactly as a real
    client would, using Ollama, proving the whole route/param-resolution/async-dispatch chain, not
    just `llm_providers.chat` in isolation.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1: the user's `.env.local` (for real-provider test credentials) landed at the repo
    root, untracked and not yet gitignored — fixed before reading a single key value.**
    *   *Reasoning:* `git check-ignore -v .env.local` returned no match; a careless `git add -A`
        could have committed real API keys. Checked and fixed this *before* reading the file's
        contents at all, then read only the variable *names* (via a `grep`/`awk` pattern that never
        prints values) to learn what to reference in code — the actual key values were never echoed,
        logged, or quoted anywhere in this session's output.
    *   *Impact:* `.gitignore` gains `.env.local`/`.env*.local`. The file was never tracked, so no
        history needs scrubbing — this closes the gap going forward, not after the fact.

*   **Deviation 2: `CONFIG["llm_provider"]`/`["llm_model"]` were silently dropped on the floor
    before this context — a real gap, not a hypothetical one.**
    *   *Reasoning:* `CTX-106.1` added `llm_provider`/`llm_model` to Rust's `DaemonConfig` and
        `build_daemon_env` specifically so a future spec could read them — but `daemon.py`'s
        `_apply_env_config` never actually read either field back out of the env-injected JSON. This
        spec is that "future spec," and the gap would have silently made provider/model selection a
        no-op if not caught here.
    *   *Impact:* `_apply_env_config` now populates both. Worth remembering: adding a field to a
        config struct on one side of a wire doesn't mean the other side actually consumes it —
        confirmed by reading `daemon.py`'s real code, not assumed from `CTX-106.1`'s own description
        of what it added.

*   **Deviation 3: AgentFlow's `GoogleGenAIProvider` default model, `gemini-2.5-flash-preview`,
    404s — found by the first real test run, not by inspection.**
    *   *Reasoning:* The real Google test failed with `404 NOT_FOUND: models/gemini-2.5-flash-preview
        is not found`. Queried Google's own live `ListModels` endpoint directly rather than guessing
        a replacement name; `gemini-2.5-flash` (no `-preview` suffix) is real and currently listed.
    *   *Impact:* `llm_providers.py` never relies on AgentFlow's own per-provider defaults — every
        entry in its own `_DEFAULT_MODELS` was verified against that provider's real, currently-live
        model list before being trusted, not copied from a library default. Anthropic's default
        (`claude-sonnet-4-6`) was verified working via the real test; not independently checked
        against Anthropic's own model list beyond that.

*   **Deviation 4: the first real provider call left an unclosed async client, surfaced by
    `RuntimeError: Event loop is closed` on cleanup — a real, if harmless, resource leak.**
    *   *Reasoning:* `chat()`'s `asyncio.run()` created a fresh event loop per call and closed it
        immediately after the response arrived, before the underlying `AsyncOpenAI`/
        `AsyncAnthropic`/`genai.Client`'s open HTTP connection could be torn down — its cleanup then
        ran on a loop that no longer existed. Caught by literally running the real calls in
        `TestRealProviderCalls`, not by code review.
    *   *Impact:* Added `_close_provider_client`/`_chat_and_close`, closing the underlying SDK client
        from inside the *same* event loop `asyncio.run()` manages, before it returns. Re-ran every
        real provider test after the fix — clean, no warnings.

*   **Deviation 5 (non-deviation, confirmed as designed): OpenAI's code path exists but is not
    verified for real in this session.**
    *   *Reasoning:* The user explicitly said to skip OpenAI — no real API key was available (the
        `.env.local` placeholder is 6 characters, clearly not a real key). `test_005` guards against
        that placeholder silently passing as "real" by requiring at least 20 characters before
        attempting a live call, skipping otherwise.
    *   *Impact:* `llm_chat("openai", ...)` is exercised only by `TEST-001`'s construction check
        (real object, right endpoint, no network call) — the actual chat round-trip is unverified.
        Stating this plainly rather than letting the other four providers' green tests imply OpenAI
        was checked too.

*   **Deviation 6 (2026-08-10, post-completion): `claude-sonnet-5` was silently broken through
    AgentFlow's `AnthropicProvider`, and both this module's own model defaults had gone stale.**
    *   *Reasoning:* Verifying the user's report that this module might be referencing outdated
        models, a live `GET /v1/models` call against Anthropic showed `claude-sonnet-5`/`claude-opus-5`
        as current, with `claude-sonnet-4-6` (this module's default) real but no longer latest.
        Attempting the newer model for real surfaced an actual bug: Anthropic rejects an explicit
        `temperature` outright for that model line (`` `temperature` is deprecated for this model``)
        and requires a different adaptive-thinking + effort interface instead of the older
        `budget_tokens` one — a real `gittielabs-agentflow` limitation, not a `hardware-agent-studio`
        bug, per this repo's own standing rule to fix AgentFlow bugs upstream. Separately, Google's
        live `ListModels` showed this module's `gemini-2.5-flash` default is real but well behind
        current (`gemini-3.5-flash`/`gemini-3.6-flash`), and that Google offers stable rolling
        aliases (`gemini-flash-latest`) specifically to avoid ever hardcoding a snapshot that goes
        stale.
    *   *Impact:* Fixed upstream in `gittielabs-agentflow` — `AnthropicProvider` now recognizes a
        `-low`/`-medium`/`-high` model-name suffix for adaptive thinking (mirroring
        `GoogleGenAIProvider`'s identical convention for Gemini) and retries once without
        `temperature` on the specific deprecation error, rather than hardcoding a model-name
        allowlist that ages out with every release. Released as `v0.8.2`
        ([GittieLabs/agentflow#7](https://github.com/GittieLabs/agentflow/pull/7)). This module's own
        `_DEFAULT_MODELS` bumped to match: `anthropic` → `claude-sonnet-5`, `google` →
        `gemini-flash-latest` (a stable alias, not a dated snapshot). All three changed defaults
        called live end-to-end through `llm_providers.chat()`, including the new thinking suffix
        (`claude-sonnet-5-low`), before being written. `component_extraction.prompt.md`
        (`CTX-202.1`'s own agent) deliberately left on `claude-sonnet-4-6` — a real check against
        `claude-sonnet-5` returned a validly-named but different package synonym ("PDIP-8" vs.
        "DIP-8"), correctly caught by `SPEC-202`'s fail-closed validation but worth its own dedicated
        verification pass rather than a drive-by change alongside this one.
