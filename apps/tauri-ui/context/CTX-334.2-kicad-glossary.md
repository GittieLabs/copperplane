# CTX-334.2: Implementation Context: A KiCad Abbreviation Glossary That Decodes Rather Than Lists

> **Spec Reference:** Links to [SPEC-334](../specs/SPEC-334-footprint-literacy-and-component-detail.md)

Follows [CTX-334.1](CTX-334.1-footprint-detail.md), which shipped the footprint detail view.
Reported by the maintainer on using it:

> *"it would be helpful to have a glossary of terms for Kicad. THT, DIP and all of the other
> abbreviations are not intuitive. Adding links or help info could save time for the user to look
> up unfamiliar ones that Kicad uses in naming."*

This context is stacked on `feat/CTX-334.1-footprint-detail`, which is open as PR #349 and not yet
merged. It contains that branch's commits as well as its own.

## 1. Feature Definition & Execution Plan

### Phase 1: Bound the vocabulary by measurement, not by memory
*   [x] Take the package families from KiCad's own `Package_*` libraries rather than inventing a
        list — BGA, CSP, DFN_QFN, DIP, LCC, LGA, QFP, SIP, SO, SON, SO_J-Lead, TO_SOT_SMD,
        TO_SOT_THT.
*   [x] Decode variants compositionally (a height letter plus a family) so `VQFN`, `TQFN`, `UQFN`,
        `WQFN`, `HVQFN` and `DHVQFN` all read without any of them being listed.
*   [x] Name a vendor's series code as a vendor's series code instead of expanding it.
*   [x] Measure coverage across every footprint KiCad ships.

### Phase 2: The surface
*   [x] "What the abbreviations mean" in the footprint detail view, read straight off the name.
*   [x] Mark a composed reading as composed, so a reader can tell a lookup from a derivation.
*   [x] A browsable, filterable list of the whole vocabulary behind "All KiCad terms".
*   [x] Both available when the footprint file itself could not be read — the vocabulary does not
        depend on the library being installed, which is when a user is most stuck.

### Phase 3: Tests
*   [x] Unit tests for the decoder, including the readings it must refuse to give.
*   [x] A corpus test against all 15,433 footprints in KiCad's own libraries.
*   [x] Component tests for both surfaces.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1: the roadmap's warning shaped the design, and was worth following.**
    `ROADMAP.md`, under SPEC-332's still-open items: *"A glossary that is not a hard-coded list.
    Fine for the dozen terms KiCad's DRC actually emits; wrong if it grows into a general PCB
    dictionary."* Written before this request existed, and this request is exactly the growth it
    warned about. The answer is that the glossary decodes rather than enumerates: 33 entries plus
    11 prefix letters explain 88.0% of the 15,433 footprints KiCad ships, including families the
    file has never seen. A flat dictionary reaching the same coverage would need hundreds of
    entries and would still miss the next variant a manufacturer invents.

*   **Deviation 2: compositional decoding produces confident wrong answers, and had to be
    demoted.** `LFCSP` composes cleanly to "Low profile, fine pitch CSP". Analog Devices means
    **Lead Frame** Chip Scale Package. The composition is fluent, plausible, and wrong — the exact
    failure mode this repo keeps paying for. Two changes came out of it: a whole-token lookup
    always wins over a composed reading, and any composed reading carries its derivation into the
    UI ("read as V + QFN") so a reader can see which of the two they are getting. `LFCSP` and `SC`
    are now explicit entries.

*   **Deviation 3: the first decoder read prefixes from the front and broke on real data.**
    Matching a known prefix at the *start* of a token handled `VQFN` and `HVQFN` and returned
    nothing for `DHVQFN`, whose leading `D` is NXP's own and appears in no standard. It now finds
    the family the token *ends* with and reads the letters in front of it, naming any it does not
    know rather than expanding it. Found by the corpus test, not by inspection.

*   **Deviation 4: `SMDIP` said "Surface-mount DIP — a through-hole chip", in one sentence.** The
    family text asserted a mounting that a prefix had already overridden. Family entries no longer
    claim a mounting; the detail view reports the real one from the pads, which is measured rather
    than inferred from a name.

*   **Deviation 5: the same `\b` trap as CTX-334.1, in a new place.** `/\b0805\b/` never matched
    `R_0805_2012Metric`, because `_` and `0` are both word characters and there is no boundary
    between them. `CTX-334.1` hit this with `_Horizontal`. It is now matched against whole tokens
    rather than with a word boundary. Twice in two contexts is a pattern worth naming: this repo's
    identifiers are underscore-separated, so `\b` almost never means what it looks like it means.

*   **Deviation 6: no links, despite the request mentioning them.** *"Adding links or help info"* —
    this delivers the help info and no links. A definition read in place costs no round trip and no
    reading of a datasheet written for a different audience, and an external URL is a maintenance
    liability that can rot silently. The one link that is genuinely specific — the datasheet the
    footprint's own file names — was already surfaced in `CTX-334.1`.

*   **Prediction, recorded for the next session to check:** the uncovered 12% is a long tail of
    vendor part codes (`RV`, `MF`, `HDSP`, `WROOM`), and I expect adding entries for them to make
    the glossary worse rather than better — they have no standard meaning, so the honest output is
    the manufacturer's name and silence about the code, which is what happens today. If a real user
    reports being stuck on one of those, that prediction was wrong and the vendor note needs to
    carry more than a name.

## 5. Verification Notes

*   Measured, not assumed: 155 libraries, 15,433 footprints, 88.0% with at least one term
    explained. The corpus test asserts a floor of 80% so a KiCad library revision does not fail the
    build, while losing a whole family still would.
*   Full UI suite: 654 tests across 36 files, all passing. No Python changed in this context, so
    the sidecar is untouched and did not need re-freezing.
*   CI on this branch: `test`, `validate-specs-and-context`, and `test` on macos-latest,
    ubuntu-latest and windows-latest all green before merge.
*   **Not verified:** nobody has clicked this in the built Tauri window yet — same gap
    `CTX-334.1` recorded. The corpus test is bound to KiCad 10's libraries at
    `/Applications/KiCad/KiCad.app`, so it skips itself entirely on Windows, on Linux, and in CI.
    That means `TEST-007` and `TEST-008` have run on exactly one machine.
