# CTX-319.2: Implementation Context: ReviewPanel in Components

> **Spec Reference:** Links to [SPEC-319](../specs/SPEC-319-ai-review.md)

Phase 2: the frontend counterpart to `CTX-319.1`'s backend foundation. First real integration --
mirrors `CTX-318.2`'s own precedent of doing Components first. `lib/chat.ts` gains the client
surface for `chat.review`; a new shared `ReviewPanel` reuses `AgentChat`'s own source-chip
rendering (extracted into a new `lib/sourceRefs.ts`, SPEC-319 §2.5) rather than a second
implementation; `PartDetail.tsx` mounts it as a sibling to `AgentChat`, not inside it.

## 1. Feature Definition & Execution Plan

### Phase 1: `lib/chat.ts` client surface
*   [x] `ReviewFinding` interface -- snake_case throughout (`general_practice`, matching
    `ChatTurn.general_practice`/`.sources_dropped`), **not** the camelCase `generalPractice` `SPEC-319`
    §2.3 itself used when first correcting `SPEC-318`'s own shape -- caught while actually
    implementing this file, since every other wire-shaped interface here is snake_case and nothing
    in this codebase camelCases a route's own JSON on the way in.
*   [x] `runReview(scope, scopeId, area, projectName?) -> Promise<ReviewFinding[]>` -- `submitJob`-shaped,
    matching `sendChatMessage`'s own precedent exactly (a real LLM call), minus a `message`
    parameter (a review's own prompt is fixed internally).

### Phase 2: extract `AgentChat`'s source-chip logic into a shared module
*   [x] New `lib/sourceRefs.ts`: `sourceChipLabel`, `isOpenableSource`, and `openSource` (the
    stateful-turned-stateless async open flow -- returns a rejected promise on failure instead of
    setting local error state, so both `AgentChat` and `ReviewPanel` can wrap it with their own
    loading/error UI). `AgentChat.tsx` now imports all three instead of defining its own local
    copies; its own `handleOpenSource` shrinks to a thin wrapper around `openSource` plus its
    existing `openingSourceKey`/`openSourceError` state.
*   [x] New `lib/sourceRefs.test.ts` -- real, direct unit tests for the extracted functions
    (a `guidance_item`'s real page resolution via a saved Part's `design_guidance`, a
    `datasheet_page`'s direct open, and two real failure cases: no `part_id` at all, and an
    unmatched quote/category). `AgentChat.test.tsx`'s own existing TEST-006/007/008 (the same
    resolution logic, exercised through the full component) were left as-is rather than rewritten
    to mock the new module -- still real, still passing, and rewriting working tests carried more
    risk than the mild duplication is worth right now.

### Phase 3: `ReviewPanel` component
*   [x] `ReviewPanelProps`: `area`, `scope`, `scopeId`, `title`, `projectName?` -- the same shape
    `AgentChatProps` already established, minus `promotionTargets` (SPEC-319 §1's own Non-Goal:
    findings are ephemeral, never promotable in this first version).
*   [x] A **Run Review** button; findings render in a dismissible list once a run completes, each
    with severity, title, detail, a per-finding general-practice marker (SPEC-319 §2.3's own
    correction from `SPEC-318`'s response-wide flag), and source chips reusing `lib/sourceRefs.ts`.
    An empty result renders "Nothing stood out." -- an honest, normal state, not silence or an
    error (SPEC-319 §3).
*   [x] Resets on `[scope, scopeId]` change, matching `AgentChat`'s own identity-reset convention --
    a stale review from a previously-viewed part must never linger once the real scope moves on.

### Phase 4: mount in `PartDetail.tsx`
*   [x] Mounted as a sibling to `AgentChat`, gated on the same `savedPart` condition -- `SPEC-319`
    §2.4's own explicit placement rule (a review is a flow step with a typed result, not a
    conversational turn, so it does not live inside `AgentChat`'s own message list).

## 4. Plan Drift & Architectural Changes

*   **Deviation 1 (real, caught while implementing, not assumed): `SPEC-319` §2.3's own corrected
    `ReviewFinding` shape used `generalPractice` (camelCase), inconsistent with every other
    wire-shaped interface in `lib/chat.ts`.**
    *   *Reasoning:* the spec's own correction (adding a per-finding flag at all, see `CTX-319.1`'s
        own Plan Drift) focused on the *presence* of the field, not its naming convention, and
        copied a camelCase habit that doesn't match `ChatTurn.general_practice`/`.sources_dropped`
        already in this exact file.
    *   *Impact:* implemented as `general_practice` (snake_case) to match. Not worth a separate spec
        amendment commit for a field-naming nit caught during implementation -- recorded here
        instead, matching this repo's own norm that Plan Drift is for what actually happened, not
        only for large decisions.
*   **Deviation 2 (a real, deliberate choice, not an oversight): `AgentChat.test.tsx`'s own
    TEST-006/007/008 were left unchanged rather than migrated to mock the new `lib/sourceRefs.ts`.**
    *   *Reasoning:* those three tests already exercise the real resolution logic end-to-end through
        `AgentChat`; the same logic now also has direct, dedicated unit tests in
        `lib/sourceRefs.test.ts`. Migrating `AgentChat.test.tsx` to mock `openSource` wholesale would
        remove real, working, already-passing coverage in exchange for eliminating a small amount of
        duplication -- not a good trade under time pressure, and not risky to defer (nothing here
        is broken, only slightly redundant).
    *   *Impact:* named explicitly as intentional so a future session doesn't assume the resolution
        logic is only tested once, or attempt an unnecessary "cleanup" that actually reduces real
        coverage.
