# CTX-312.2: Real click-through fix -- Save Project and Link to folder gave no visible confirmation

> **Spec Reference:** Links to [SPEC-312](../specs/SPEC-312-application-shell-project-portability-persistence.md)

`CTX-312.1` shipped with both suites green, but -- exactly as its own Plan Drift predicted -- had
not yet had a human click-through. The user's own first real click-through reported it directly:
"i clicked save on test 1 project and nothing appeared to happen. i clicked link and chose a folder
and then save project and also did not see an apparent change."

## 1. Feature Definition & Execution Plan

### Phase 1: root-cause investigation -- confirmed no functional bug, a missing feedback affordance
*   [x] Verified the real backend routes end-to-end (`daemon.project_save`/`project_load`), not
    assumed: created a project, linked a real temp directory, reloaded, and confirmed the real
    `<directory>/.hardware-agent-studio/project.json` file existed on disk with the right
    contents -- the exact same call sequence `App.tsx` makes. All correct.
*   [x] Root cause: `handleSaveProject`/`handleLinkDirectory` (`CTX-312.1`) had no success
    confirmation at all beyond a transient "Saving…" button label reverting to "Save Project," and
    the "Link to folder…" button's own label change to "Linked: `<path>`" is small, gray, and easy
    to miss -- a real successful save looked identical to nothing happening, exactly matching the
    user's own report.

### Phase 2: real, visible confirmation, matching this app's own established pattern
*   [x] New `projectActionMessage` state in `App.tsx`; both handlers set a real, specific message on
    success ("Linked to `<path>`" / "Project saved.") -- matching `CTX-311.13`'s own already-shipped
    "Exported to `<path>`" precedent exactly, not a new pattern invented here. Persists until the
    next real action (project switch, another Link/Save), not on an auto-dismiss timer.
*   [x] Rendered as a real, distinct green confirmation line beneath the action row, separate from
    the existing red error line.
