# CTX-335.1: New Project Wizard

> **Spec Reference:** Links to [SPEC-335](../specs/SPEC-335-new-project-wizard.md)

Replaces the two-field sidebar create form with a guided first run in the main content area, ending
in a real review of the project's current state.

## What this replaces

Creating a project today is a name and an optional intent typed into a 192px sidebar column, with
**no way to cancel**, after which the user lands on a tabbed view with nothing in it. Nothing in the
app works without a linked `.kicad_pro` (`SPEC-325`), and creation never mentions one.

## 1. Feature Definition & Execution Plan

### Phase 1: The wizard shell, in the main content area ✅

*   [x] `NewProjectWizard` renders in the main area; the tabbed project view is not shown until the
        wizard completes.
*   [x] Cancel at any step, leaving no project behind — nothing is written until submit.
*   [x] The sidebar's inline create form is replaced by an action that opens the wizard.

### Phase 2: Name and KiCad project ✅

*   [x] Step 1 takes the project name, rejecting a name that already exists rather than silently
        merging into it.
*   [x] Step 2 offers a `.kicad_pro` picker, a way to open KiCad, and **Skip for now**.
*   [x] Skipping is recorded as a real state, not an error: the project is created unlinked.

### Phase 3: Intent by conversation ✅

*   [x] Step 3 asks what the user is building, sends it to the project agent, and shows the
        assistant's summary back for confirmation.
*   [x] Confirming writes `intent` through `project.set_intent`.
*   [x] The user can edit the summary before confirming — it is their project, not the agent's.

### Phase 4: The review, streamed ✅

*   [x] Step 4 runs parity, component envelopes, ERC and DRC as four independent jobs, rendering
        each as it lands rather than after all four.
*   [x] A failed check reports itself and does not cost the user the other three.
*   [x] Four buttons — Overview, Components, Schematic, PCB, Enclosure — dismiss the wizard onto the
        chosen tab.

### Phase 5: Banners for what is missing ✅

*   [x] A project with no linked `.kicad_pro` carries a persistent banner naming what is missing and
        what it stops working, with a way to link one.

### Not in this context

*   **First-run onboarding** (`SPEC-336`) — providers, tool detection, the welcome screen. This
    context starts once the app is usable.
*   **What a returning user sees on Overview.** Deliberately unresolved; the Overview's status cards
    were removed as a guess, and this wizard must not quietly become the answer to that question.

## 4. Plan Drift & Architectural Changes

**Two decisions settled before implementation**, recorded in `SPEC-335` §2:

*   **Step 2 does not block.** A user with no `.kicad_pro` finishes anyway, with a banner. This
    follows `SPEC-336`'s no-trapping rule, which the maintainer arrived at by noticing that the
    manual setup path has never gated anyone: gating the guided path would punish the user who
    asked for help.
*   **Step 4 streams.** The four checks are already independent `ASYNC_ROUTES` jobs, so rendering
    each as it completes needs no new mechanism — and specifically **no AgentFlow streaming**, which
    was raised as a possible blocker. Only token-by-token rendering of the final summary would need
    that, and the summary arrives whole like every other LLM call in the app.

**Deviation 1 — Phase 1 needed a completion path it was not scoped to have.** The phase is the
shell, and step 1's real name field belongs to Phase 2. But "the tabbed view is not shown until the
wizard completes" cannot be demonstrated without a way to complete, so a minimal name input and a
Create button live in the shell. Phase 2 replaces them with the real step, including the
duplicate-name check.

**Deviation 2 — three Rail tests were deleted rather than adapted.** They covered the inline create
form's name field, its optional intent box and its disabled Add button. That form no longer exists
in the Rail; the behaviours move to the wizard and are tested there. Adapting them would have left
tests asserting a surface that is gone.

**Deviation 3 — the review runs before the project exists, and that turned out to be free.** The
plan assumed step 4 might need a saved project to check. It does not: `check_schematic_parity`,
`component_envelopes`, `check_board` and `check_schematic` all take explicit paths, so the whole
review runs against the picked `.kicad_pro` with nothing written. That is what keeps "nothing is
written until the last step" true through the entire wizard rather than only up to step 2 — and it
means Cancel stays safe on the last screen, after the user has seen their results.

**Deviation 4 — intent is summarised by `llm.chat`, not the project agent.** The project agent is
scoped to a project that does not exist yet. Using it would have forced an early write for the sake
of asking a question, trading away the guarantee above. A plain chat call does the same job.

**Deviation 5 — a failed summary keeps the user's own words.** Not planned. If the LLM call fails,
the description the user typed becomes the summary, with a line saying so. Losing what someone
wrote because a network call failed is the kind of small betrayal that makes an app feel unsafe.

**Deviation 6 — the intent step had no way to say yes.** Found by the maintainer on first use:
*"im stuck on the what are you building step. I don't have a way to move on or acknowledge the
summary."* The forward button on every step after the first was labelled **Skip for now**, so a user
who had described their project, read the summary and agreed with it could only "skip" past it. The
label was also the only forward action, which made the step read as unfinishable.

Now the forward action is real on every step — *Next*, or *Use this* on the intent step — and
**Skip for now appears only when there is genuinely something to skip**, disappearing once the step
is done.

**Deviation 7 — skip was styled as an equal, and placed as one.** Same colour as the primary action
and sitting between Back and Next: *"I don't want to encourage the skip step."* It is now a quiet
underlined link on the far right of the row, away from Back and the forward action.

**Deviation 8 — a description the user never summarised is kept.** They may type an answer and move
on without pressing Summarise; discarding it because they did not use the optional LLM step would
throw away the very thing the step asked for.
