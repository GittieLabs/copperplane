# CTX-310.2: Implementation Context: Board Profile Import UI

> **Spec Reference:** Links to [SPEC-310](../specs/SPEC-310-enclosure-from-board-profile.md)

The frontend half of `SPEC-310`: a `.kicad_pcb` file picker in the Enclosure area's existing
board-driven-mode UI, wired to `CTX-310.1`'s new `pcb_path` parameter. Split from `CTX-310.1`
deliberately, the same daemon/UI split `CTX-309.1`/`CTX-309.2` already established for `SPEC-309`.

## 1. Feature Definition & Execution Plan

### Phase 1: `lib/enclosure.ts` -- `pcb_path` param + `pickPcbFile`
*   [x] `EnclosureParams` gains an optional `pcb_path` field, mirroring `daemon.py`'s own new
    parameter exactly.
*   [x] `pickPcbFile()`: a real native file picker filtered to `.kicad_pcb`, mirroring
    `boardAdvisor.ts`'s own `pickSchematicFile` pattern precisely (same `@tauri-apps/plugin-dialog`
    call shape, same `null`-on-cancel-is-not-an-error contract).

### Phase 2: `EnclosurePanel` -- a third mode, always offered
*   [x] A new `'file'` mode alongside the existing `'manual'`/`'board'` modes. Unlike `'board'`
    (gated on `kicad_available`), `'file'` is offered unconditionally -- SPEC-310's whole point is
    not needing a live KiCad connection at all.
*   [x] File mode reuses `'board'` mode's existing geometry fields (height, wall thickness,
    clearance, fillet radius, standoff height) unchanged -- only the outline/hole *source* differs
    between the two modes, not the geometry parameters themselves.
*   [x] A "Choose .kicad_pcb file…" button calls `pickPcbFile()`; the picked path (or "No file
    selected.") is shown inline. **Generate is disabled until a real path has been picked** -- unlike
    manual/board mode, file mode has no usable default state to fall back to.
*   [x] `handleGenerate`'s param construction extended with a `mode === 'file'` branch: spreads
    `boardParams`, adds `pcb_path`, omits `width`/`depth` (matching board mode's own omission).

## 4. Plan Drift & Architectural Changes

*   **Deviation 1: file mode reuses board mode's entire geometry-field set rather than introducing
    its own.** `freecad_generate_enclosure`'s geometry parameters (`wall_thickness_mm`,
    `clearance_mm`, `fillet_radius_mm`, `standoff_height_mm`) are identical regardless of whether the
    outline/hole data came from a live connection or a file -- only `board_outline`/`standoffs`'
    *source* differs. Giving file mode a separate, parallel set of input fields would have
    duplicated `boardParams`' state and JSX for no real behavioral difference; sharing it directly
    keeps the two board-driven modes' geometry inputs trivially consistent with each other.
*   **Deviation 2: no live click-through in the real running Tauri window this session -- the same,
    already-documented recurring gap `CTX-309.2` named one context ago for its own file-picker work.**
    This session has no automation surface for the native macOS window (no accessibility/screen-
    recording permission, no `cargo-tauri` CLI installed in this environment). Named explicitly here
    rather than silently treated as equivalent to a real human click-through, per `CLAUDE.md`'s "state
    what was not verified" norm.
