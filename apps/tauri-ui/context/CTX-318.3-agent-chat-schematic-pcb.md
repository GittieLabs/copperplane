# CTX-318.3: Implementation Context: AgentChat in Schematic and PCB

> **Spec Reference:** Links to [SPEC-318](../specs/SPEC-318-in-context-agent-chat-and-review.md)

Phase 3 of 6 in the user's own confirmed order: foundation (`CTX-318.1`) → Components (`CTX-318.2`) →
**Schematic/PCB** → Enclosure → project intent/Overview → finish deleting `parseCommand`. Both areas
are project-scoped, not part-scoped -- there is no single Part to offer as a promotion target, only
"this project" (mirrors `CTX-318.2`'s own `componentsPromotionTargets`, minus the part branch).

## 1. Feature Definition & Execution Plan

### Phase 1: mount `AgentChat` in `SchematicAdvisor.tsx` and `BoardAdvisor.tsx`
*   [x] Both components stay mounted across every area tab already (`App.tsx` hides them with CSS,
    not unmount) -- `AgentChat` is mounted as a sibling inside each component's own existing outer
    wrapper, at the foot of the view (SPEC-318 §5's own "a collapsible chat panel at the foot of each
    area"), matching `PartDetail.tsx`'s own mount point.
*   [x] `SchematicAdvisor.tsx`: `area="schematic"`, `scope="project"`, `scopeId={`${projectName}:schematic`}`
    (SPEC-206 §2.2's own real `<project_name>:<area>` scope-id format for project-scoped areas),
    `title="Ask about the schematic"`, `projectName={projectName}`,
    `promotionTargets={[{ label: 'this project', scope: 'project', id: projectName }]}`.
*   [x] `BoardAdvisor.tsx`: same shape, `area="pcb"`, `scopeId={`${projectName}:pcb`}`,
    `title="Ask about the board"`. `BoardAdvisor`'s own real structure has an outer component
    wrapping a separate inner `BoardCheckSection` sub-component -- `AgentChat` is mounted as a
    sibling to `<BoardCheckSection .../>` inside the outer wrapper, not inside the sub-component.
*   [x] Neither component has an optional `projectName` -- both already require it as a non-optional
    prop, so unlike `CTX-318.2`'s Components case, there is no "no project open" state to handle here.

### Phase 2: tests
*   [x] `SchematicAdvisor.test.tsx` and `BoardAdvisor.test.tsx` each gain a stub for `./AgentChat`,
    matching `PartDetail.test.tsx`'s own precedent (`CTX-318.2`) -- keeps each file's own tests
    focused on *whether it wires AgentChat correctly* (real `area`/`scope`/`scopeId`/`title`/
    `projectName`/`promotionTargets`), not on AgentChat's own internals (`AgentChat.test.tsx` already
    covers those).
*   [x] **The same trap recurring a third time, not assumed -- found by actually re-running the full
    suite, not just the two files just edited.** Fixing the leaf-level `SchematicAdvisor.test.tsx`/
    `BoardAdvisor.test.tsx` files alone left `App.test.tsx` broken: it does not mock
    `./components/SchematicAdvisor` or `./components/BoardAdvisor` at all (only their underlying
    `./lib/boardAdvisor` calls), by design -- both real components stay mounted there too. With both
    real, unmocked `AgentChat` panels now in the DOM simultaneously (Schematic's and PCB's), the real
    "Send" button and message placeholder collided with the Overview area's own chat input, making
    `App.test.tsx`'s own `sendMessage()` helper (`getByRole('button', { name: 'Send' })`) ambiguous.
    Fixed by adding the same `./components/AgentChat` stub to `App.test.tsx` as well.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1 (real, found by re-running the full suite, not assumed): the AgentChat-rendered-
    unmocked trap recurred a third time, this time one level up the tree from where it was fixed.**
    *   *Reasoning:* `CTX-318.2` established the fix pattern (stub `./AgentChat` in the consuming
        component's own test file) and applied it correctly to `PartDetail.test.tsx`. Applying the
        same fix to `SchematicAdvisor.test.tsx`/`BoardAdvisor.test.tsx` was necessary but not
        sufficient -- `App.test.tsx` renders the real `SchematicAdvisor`/`BoardAdvisor` components
        directly (never mocks them, since App.tsx's own routing/mount behavior for those areas is
        what that file tests), so it inherited the same real, unmocked `AgentChat` problem
        transitively the moment `CTX-318.3`'s mount code landed -- with two real AgentChat panels
        live simultaneously (Schematic's and PCB's, since `App.tsx` keeps both mounted across tabs),
        colliding with Overview's own "Send" button and breaking `App.test.tsx`'s `sendMessage()`
        helper via an ambiguous `getByRole` match.
    *   *Impact:* fixed by adding the same `./components/AgentChat` stub to `App.test.tsx`. Worth
        naming explicitly for whichever phase mounts `AgentChat` next (Phase 4, Enclosure): any test
        file that renders a real, unmocked component that itself now mounts `AgentChat` -- not just
        the component's own direct test file -- needs the same check, one level further up the tree
        each time a new area adopts `AgentChat`.
