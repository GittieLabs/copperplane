# CTX-113.4: Implementation Context: Severity You Can See

> **Spec Reference:** Links to [SPEC-319](../specs/SPEC-319-ai-review.md)

The maintainer, on a real board review: *"I almost missed the additions. I see a suggestion and an
info block. But those still blend in."* A warning, a suggestion and an info sat on the identical
surface, distinguished only by a five-character label in a slightly different grey.

## 1. Feature Definition & Execution Plan

### Phase 1: give each severity its own ground
*   [x] Three new tokens, defined in all three theme blocks: `--color-surface-warning`,
    `--color-surface-suggestion`, `--color-surface-info`.
*   [x] Warm and raised for a warning, cool and level for a suggestion, recessed for info. A
    luminance ramp first and a hue second, so the ordering survives where the tints render poorly.

### Phase 2: guard them, since nothing else in the suite looks at a colour
*   [x] Every theme defines all three. A token present in one block and missing from another falls
    back to whatever it inherits, in one theme only -- `CTX-336.1`'s failure exactly.
*   [x] Body text stays above 4.5:1 on each.
*   [x] The three are actually distinguishable from one another.

## 4. Plan Drift & Architectural Changes

**1. My first guard measured the wrong thing, and it failed on colours that are obviously
different.** I wrote the separation check as a WCAG contrast ratio, because that is the metric this
file already uses. A contrast ratio is **luminance only**: the warm amber and the cool blue-grey
scored **1.01**, which reads as "identical", when the hue is the entire point of the pair. The
tempting move was to brighten the warning surface until the number went up -- changing a design to
satisfy a measurement that does not model the goal.

Replaced with CIELAB ΔE, which includes hue. Roughly 2.3 is the just-noticeable difference and 6 is
a difference a reader registers without looking for it. WCAG stays where it is the right metric --
text legibility on each surface.

**2. It caught a real problem on the first run, before the metric changed.** The original light-mode
suggestion and info tints were ΔE 2.34 apart -- at the very edge of noticeable, which is precisely
the flaw being fixed, reintroduced one level down by picking values by eye. The final set is ≥7
apart everywhere.

**3. Confirmed the guard can fail.** Set the suggestion surface to a near-copy of the warning
surface and watched it reject the pair at ΔE 0.66. A colour check nobody has seen fail is not
evidence, and this file exists because of a colour bug that shipped past 728 passing tests.

**4. Not verified: how it looks.** Three grounds, plus the accent left border and pill on findings
this app computed itself, is a lot of signal on one card. The numbers say the tiers are
distinguishable and the text is legible; whether the result reads as calm or as a fruit salad is a
judgement no test here can make, and the previous round of this same surface took two looks to get
right.

**5. Reverted after one look, and the earlier note said why.** This context closed with *"whether
the result reads as calm or as a fruit salad is a judgement no test here can make"*. The maintainer
looked at both themes and answered it: *"I don't think the background color is needed. I think the
green left border and the green chip will be sufficient."*

Every number was fine. The tiers were ΔE 7 or more apart, the text was 8.6:1 at worst, and the
guard had already proved it could fail. None of that was the question. On a list where every
finding happened to be a warning, the tint carried no information and read as noise -- and the
origin signal it was competing with is the one that matters, because that is the thing no other
tool in the toolchain reports.

Reverted whole: the three tokens, the component's use of them, and the three tests. The ΔE helper
went with them rather than being left as dead code; the reason it existed is recorded in drift
entry 1 and is worth remembering the next time a colour needs measuring, because a WCAG ratio will
be the wrong tool then too.

**Kept from this round:** the severity label already had distinct colours and still does. What was
removed is the ground behind it, not the distinction.
