# CTX-311.9: Lighting rebalance: CTX-311.6's own softening overcorrected once the material was actually fixed

> **Spec Reference:** Links to [SPEC-311](../specs/SPEC-311-enclosure-refinement-interactive-preview.md)

`CTX-311.8`'s camera fix worked -- the user's next screenshot showed the real hollow shell clearly for
the first time: cavity, floor, and standoff posts all visible from a real 3/4 angle. The next real
feedback, after manually orbiting to what they called the best available angle: "it is still hard to
see where the edges of the floor meet" the walls. A real, different problem again -- not camera
framing (already fixed) and not material color/metalness (already fixed) -- this one is about
per-face lighting contrast.

## 1. Feature Definition & Execution Plan

### Phase 1: diagnosis
*   [x] `CTX-311.6` raised `ambientLight` to `1.1` and lowered the main `directionalLight` to `0.3`
    in response to a real "hard, dark shadows" complaint -- a real, reasonable-looking fix at the
    time, but made while the mesh was *still* rendering as a fully metallic surface (`CTX-311.7`'s
    own, not-yet-found bug). A near-black metallic surface reads as harsh regardless of light
    balance; `CTX-311.6` never actually tested whether toning down the lights fixed anything, because
    the real cause was one layer deeper.
*   [x] With the material now real and matte (`metalness: 0`, `CTX-311.7`), that same high-ambient/
    low-directional balance works directly against the user's newest complaint: `ambientLight`
    contributes uniform brightness regardless of a face's own normal direction, so raising it too far
    flattens the real brightness difference between the floor (facing up, toward the main light) and
    a vertical wall (facing sideways) -- exactly the contrast that makes their shared crease/edge
    visible at all. The previous "harsh shadow" complaint and this "can't see the edges" complaint
    are two ends of the same real dial; `CTX-311.6` pushed it one way based on a misdiagnosed cause
    and this context pushes it back, now with the real cause (the metallic bug) actually gone.

### Phase 2: fix
*   [x] `EnclosureViewer.tsx`: `ambientLight` intensity lowered from `1.1` to `0.5`; the main
    `directionalLight` raised from `0.3` back to `1.0`; the dim fill `directionalLight` raised
    slightly, `0.15` to `0.25`, so no face reads as fully black even at a grazing or opposite angle
    to the main light -- real per-face contrast for edge definition, without reverting all the way to
    `CTX-311.6`'s own original "too harsh" starting point (`ambient: 0.6, directional: 0.8`, no fill
    light at all).

### Phase 3: verification
*   [x] `npx tsc -b` clean; `npx vitest run` -- 215 passed (no pure-function logic changed here, only
    JSX light-intensity props, so no new unit tests -- matches this repo's own convention of not
    unit-testing plain prop values with no branching behavior).

## 4. Plan Drift & Architectural Changes

*   **Deviation 1: `CTX-311.6`'s own lighting fix is now understood to have been diagnosing a
    symptom of a bug (`CTX-311.7`'s metallic-material issue) that hadn't been found yet, not a real,
    independent lighting problem.** Recorded plainly: two real user complaints about the same visual
    surface -- "too harsh" (`CTX-311.6`) and "too flat, can't see edges" (this context) -- were never
    actually in tension once the real root cause was separated out. The metallic-material bug alone
    was fully capable of producing a "harsh, near-black" look at *any* reasonable light balance, so
    `CTX-311.6`'s light rebalance was addressing a symptom of a bug it didn't know existed yet, and
    this context's own fix is really the first time the *actual* lighting balance question -- given a
    correctly matte material -- has been asked at all.
