## 4. Plan Drift & Architectural Changes

*   **Deviation 1 (a real, deliberate scope boundary set before writing any code, not discovered
    mid-implementation): the native Design-menu "Run Review" item is deferred to its own later
    phase, not folded into this one per area.**
    *   *Reasoning:* `SPEC-319` §2.4 names the Design submenu integration per area, which could read
        as "each area's own phase should include its own menu item." But `core/tauri-rust/src/menu.rs`
        is one file shared by all three applicable areas (Schematic/PCB/Enclosure) -- touching it
        three separate times across three separate phases risks merge friction between them and
        three separate, smaller Rust-side test/verification passes instead of one coherent one.
    *   *Impact:* Schematic and PCB (this phase) and Enclosure (`CTX-319.4`) each ship with the
        in-area **Run Review** button only; a dedicated later phase adds all three Design submenu
        items, `lib/ipc.ts` event constants, and each area's own `menuCommand` handling in one pass.
        Named here explicitly so a future reader doesn't assume this phase's own scope is incomplete
        by oversight rather than by design.
