# CTX-326.4: The Labelled Bounding Solid

> **Spec Reference:** Links to
> [SPEC-326](../specs/SPEC-326-component-volume-placeholders.md)

## 1. Feature Definition & Execution Plan

`SPEC-326` §1 promises *"a footprint with no resolvable model gets a labelled bounding solid, a
clearance proxy, never presented as a real model."* Three contexts have built everything that feeds
it — `CTX-326.1` reads courtyards, `CTX-326.2` sources Z and recommends an interior height,
`CTX-326.3` made the board the source of truth — and **nothing renders any of it**. The enclosure
preview today is a shell, standoffs and a lid; no component geometry of any kind has ever appeared
in it.

So this context is the one that puts a volume in the box, and its whole risk is that a solid in the
**wrong place** renders perfectly and is silently wrong. That is the failure this repo keeps paying
for, so Phase 1 is verification rather than plumbing — the `CTX-114.1` ordering, for the same
reason.

### Phase 1: Prove a solid lands where it is supposed to, before building the pipeline that makes many

*   [ ] Parse `(at x y [rot])` from each board footprint in `kicad_board.read_board_footprints`.
        It is not read today; the record carries reference, footprint, value and layer only.
*   [ ] Place **one** box into a real generated enclosure and assert its position **in the exported
        file**, not in the arguments passed to the exporter. A test that checks what it just passed
        in cannot fail for the reason this phase exists.
*   [ ] Assert against the transform standoffs already use — `x - board_outline["x_mm"] + margin`.
        That mapping is established and correct; reusing it is the point, and a placeholder landing
        somewhere a standoff would not is the bug being hunted.
*   [ ] Verify with FreeCAD actually installed, skipping cleanly when it is not.

### Phase 2: Every component that has a height, and none that does not

*   [ ] A solid per component whose envelope carries `x_mm`, `y_mm` **and** a non-null `z_mm`.
*   [ ] **A component with `source: "unknown"` gets no solid at all.** `SPEC-326` §2.3: there is no
        fifth source, and a default height fails as a physical object that does not fit. An absent
        volume is the honest rendering of an unknown one.
*   [ ] Rotation applied from the footprint's own `at` angle, so a rotated rectangular part occupies
        the space it really occupies.
*   [ ] Components read from the **board**, per `CTX-326.3` — the same read the numbers are quoted
        from, not a second one that can drift.

### Phase 3: Measured and stated are visibly different, and neither is mistaken for real geometry

*   [ ] Placeholder solids exported as their own mesh group with a distinct material, reusing the
        mechanism `CTX-311.6` built for the shell's inner and outer surfaces.
*   [ ] **Preview only: placeholders are in the GLB and never in the STEP.** The GLB answers "will
        the lid close" and carries the visual distinction that labels it. The STEP is the
        fabrication artifact — a stated envelope inside it opens in any CAD tool as ordinary solid
        geometry with nothing to mark it, which is exactly the mistaking `SPEC-326`'s second
        non-goal forbids.
*   [ ] A solid whose height came from a real model and one whose height a user typed are
        distinguishable, because `SPEC-326` §2.4 asks the user to be able to tell without asking.

### Phase 4: Say it in words too

*   [ ] The enclosure panel names how many volumes are shown, how many are stated rather than
        measured, and how many components are missing entirely because their height is unknown.
*   [ ] The last of those is the one that matters and the easiest to omit: a preview showing eight
        of ten parts looks complete. `CTX-326.2` already warns that the real minimum may be taller;
        this is the same warning made visible in the geometry.

`TEST-003` is the one this context turns on. It must read the **exported file** and locate the
solid, because a test that asserts the arguments handed to the exporter passes just as happily when
the transform is wrong — and a box in the wrong place renders perfectly.

`TEST-008` exists because it is the phase most likely to be quietly skipped: nothing breaks if a
placeholder ends up in the STEP, and the failure surfaces only when somebody opens it in CAD and
believes it.

## 4. Plan Drift & Architectural Changes

*   **Prediction 1: the coordinate transform will be right first time and the rotation will not.**
    The transform is already written and proven for standoffs, so reusing it is low risk. Rotation
    is new: KiCad's `at` angle is counter-clockwise in a Y-down board coordinate system, and the
    enclosure is built in FreeCAD's Y-up frame. A sign error there produces a box that is rotated
    the wrong way, which for a symmetric part is invisible and for an asymmetric one is a clearance
    answer that is wrong in a direction nobody checks. If this turns out to be backwards, it belongs
    here.

*   **Prediction 2: building the boxes will not need FreeCAD.** They are axis-aligned rectangular
    solids at known positions, and the GLB export already goes through `trimesh`. Generating them
    directly rather than round-tripping through a headless FreeCAD subprocess should be simpler,
    faster and easier to test — and it keeps placeholders structurally separate from the shell,
    which Phase 3 needs anyway. Recorded as a prediction because "should be simpler" is exactly the
    kind of claim that turns out to have a reason it was not done that way.
