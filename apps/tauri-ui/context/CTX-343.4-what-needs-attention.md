# CTX-343.4: The Findings Nobody Could See

> **Spec Reference:** Links to
> [SPEC-343](../specs/SPEC-343-the-guided-path.md)

The packs have been computing findings since 2026-09-10 and **nothing rendered them.**
`project.considerations` returned `needs_attention` on every load; `WhatYouGotRight` read `cleared`
and `checked` only. R1's placeholder value and the `+5V`-on-`VIN` finding were worked out each time
and shown to nobody.

`SPEC-343` §2.6 had already settled the shape. It was never built.

---

## 1. Feature Definition & Execution Plan

### Phase 1: Render what the packs raised — DONE

*   [x] A card on Overview, per §2.6 — no modal, no redirect, nothing arriving unbidden.
*   [x] A count, which is the *"signal that something changed"* §2.6 asked for and the whole of it.
*   [x] Each finding leads with **what it is about**, so `SPEC-210` §2.2's naming rule survives to
      the screen instead of stopping at the daemon.
*   [x] A `cited` claim shows its source, since `make` refuses to build one without.
*   [x] Silent when the guided path is off, and silent when there is nothing to say.

### Phase 2: One read for the whole tab — DONE

*   [x] `project.considerations` runs a netlist export; two cards showing two halves of one answer
      must not each pay for it.
*   [x] The fetch lifted into `Overview`, both cards handed the result.

## 4. Deviations & Discoveries (Plan Drift)

*   **This was found by trying to photograph it.** `guides/what-it-notices.md` shipped on 2026-09-11
      describing Overview raising design considerations. Placing an illustration for that page meant
      looking for a screenshot showing a finding — and there was none, in 51 captures, because the
      app has never displayed one.

    The guide was written from the specs and the daemon's behaviour, both of which were correct. The
    gap was between the route and the render, and nothing in either suite spans it: the daemon tests
    assert `needs_attention` is computed, the frontend tests assert `cleared` is shown, and no test
    asked whether anything consumed the first.

*   **`SPEC-343` §2.6 had already designed this**, which is the part worth noticing. *"A count on
    the Overview tab: a signal that something changed, which the user may ignore entirely. No modal,
    no redirect, no chat message arriving unbidden, no stage advanced on their behalf."* The design
    question was settled; the building never happened, and the spec closed as `Completed` anyway.

*   **The card leads with the reference, not the sentence.** `SPEC-210` §2.2's safety property is
    that every consideration names something real the user can go and look at — the daemon refuses
    to build one otherwise. Rendering only the explanation would enforce that rule all the way to
    the last step and then drop it.

*   **One read, not two.** Adding a second card that called `projectConsiderations` would have run a
    `kicad-cli` netlist export twice on every visit to the tab. The fetch moved into `Overview` and
    both cards take the result. `TEST-026` pins it, and is one of the three that cannot fail on the
    old code — worth having anyway, because the obvious way to write this card is the wrong one.

*   **A fixture made one of my own tests fail for the wrong reason.** `TEST-026` put the *same*
    explanation in `needs_attention` and `cleared`, so once both cards rendered, `getByText` matched
    twice and the failure read like a routing bug. Two different findings now, which is also what
    the real data looks like.

*   **Verified in the running app**, which this one had to be. The defect existed *because* nobody
    looked at the screen, so a green suite and a correct route would have been the same evidence
    that missed it the first time.

    The maintainer opened Overview on the tutorial project: **What needs attention · 2**, `R1`'s
    placeholder value and the `+5V`-on-`VIN` finding, each leading with its reference, with the
    second ending in its question. That capture is now the illustration for
    `guides/what-it-notices.md` — the page that described this surface for a day before it
    existed.
