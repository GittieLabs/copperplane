# CTX-307.2: Open File Error Handling

> **Spec Reference:** Links to [SPEC-307](../specs/SPEC-307-part-detail-library-export.md)

## 1. Feature Definition & Execution Plan

Real bug found by live user testing: `CTX-307.1`'s own "Open symbol" button, and its `CTX-308.6`
counterpart "Open footprint" (same real pattern, different file, same fix), called `open()` from
`@tauri-apps/plugin-shell` fire-and-forget -- no `await`, no `.catch`, no error state. If the OS has
no default file association for `.kicad_sym`/`.kicad_mod` (very plausible on a machine without
KiCad's file associations registered), the returned promise rejects and the rejection was silently
swallowed: no visible file opens, no error, nothing -- exactly what the user reported ("The open
button for the sym and footprint do not open them or at least there is no indication they are
open"). `handleOpenCitation` (`CTX-205.4`) already established the correct real pattern -- `await
open(...)` inside `try/catch`, surfacing failure via a real error state -- this context applies that
same shape to both remaining callers.

### Phase 1: `PartDetail.tsx`
*   [x] `handleOpenSymbol`/`handleOpenFootprint`: real, awaited, try/caught, surfacing failure via
    the existing `exportError`/`exportFootprintError` state (no new state needed).

### Phase 2: tests
*   [x] `PartDetail.test.tsx`: a real `open()` rejection for each button now shows its real error
    message, not a silent no-op.

## Files
- `apps/tauri-ui/src/components/PartDetail.tsx` -- the fix.
- `apps/tauri-ui/src/components/PartDetail.test.tsx` -- new tests.

## Verification
- `npx vitest run` -- full suite passing (328+2 new), no regressions.
- **Named, honest, real limitation**: this fixes the silent-failure symptom (a real error now
  surfaces), but does not solve the underlying real cause the user hit -- no OS file association for
  `.kicad_sym`/`.kicad_mod` on a machine without KiCad's associations registered. That's a real,
  separate, environment-configuration question, not a bug this app's own code can fix; the honest
  fix here is making the failure visible, not making the OS open the file anyway.
