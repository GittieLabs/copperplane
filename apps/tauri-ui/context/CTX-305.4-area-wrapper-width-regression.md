# CTX-305.4: Implementation Context: Area Wrapper Width Regression

> **Spec Reference:** Links to [SPEC-305](../specs/SPEC-305-app-shell-navigation.md)

Real, user-reported bug, found by live use of the Components tab: the search input rendered far
narrower than intended. Root-caused directly, not guessed — `git log -S` confirms the
`components-area`/`schematic-area`/`pcb-area`/`enclosure-area` wrapper `<div>`s `CTX-306.2`
introduced (the "stay mounted, hide via CSS instead of unmounting" pattern) never carried a width
class: `className={view.area === 'x' ? undefined : 'hidden'}`. `App.tsx`'s `<main>` is
`flex flex-col items-center`, which shrinks any unstretched flex child to its own content width
(`items-center` overrides the default `stretch` behavior) — so each of these wrapper divs shrank to
content width, and every area's own inner `w-full max-w-4xl` content ended up referencing an
already-narrow parent rather than the real available width. This silently reintroduced the exact
class of bug `CTX-305.2` already fixed once (`every tab stuck at a 448px content column`) — `CTX-305.2`
fixed each area's *own* content wrapper; `CTX-306.2`'s *new*, always-mounted outer wrapper divs (added
afterward) simply never had the same class applied to them.

`Overview` is unaffected — it's still the one area that's plainly conditionally rendered
(`{view.area === 'overview' && <Overview .../>}`, no `CTX-306.2`-style wrapper div at all, confirmed
by reading it directly), so its own root element's `w-full max-w-4xl` (from `CTX-305.2`) already
applies with no extra layer in between.

## 1. Feature Definition & Execution Plan

### Phase 1: Add the missing width class
*   [x] `App.tsx`: each of the four wrapper divs' active-state class changed from `undefined` to
    `'w-full'`. The `hidden` inactive-state class is unchanged.

### Phase 2: A real regression test, unlike `CTX-305.2`'s pure-value-swap change
*   [x] `App.test.tsx`: `CTX-305.2` itself reasoned that a `max-w-md` -> `max-w-4xl` value swap
    "carries no independent behavior to unit-test." This is different -- a *missing* class caused a
    real, silent regression once already, and `not.toContain('hidden')` (the existing test's own
    assertion at the same spot) would not have caught it, since `undefined` also doesn't contain
    `'hidden'`. New test asserts the real class value (`'w-full'`, not just "not hidden") for all
    four areas.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1 (non-deviation, confirmed as designed): this fix does not touch `CTX-305.2`'s own
    named, deliberately-left, separate quirk (a `w-full`+`max-w-*` flex item inside an
    `items-center` flex-col container renders flush-left, not centered).**
    *   *Reasoning:* Restoring `w-full` on these wrapper divs reproduces the exact same flush-left
        behavior every other already-widened area (including `EnclosurePanel`, `CTX-305.2`'s own
        example) already has — not a new inconsistency, and not the bug the user reported (which
        was specifically about wasted/narrow width, not centering).
    *   *Impact:* None -- visual parity with every other tab, matching `CTX-305.2`'s own precedent
        exactly.
