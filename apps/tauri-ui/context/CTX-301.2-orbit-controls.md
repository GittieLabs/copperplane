# CTX-301.2: Camera Controls for the 3D Viewer

> **Spec Reference:** Links to [SPEC-301](../specs/SPEC-301-3d-viewer.md)

**Scope note:** closes a real, narrow gap `CTX-301.1` Deviation 5 recorded — `SPEC-301` §2's own
Cross-Module Impacts section named `@react-three/drei` "for the loader/camera-controls convenience
it provides," but `EnclosureViewer.tsx` never actually rendered a control from it. This context is
exactly that one fix, not a broader viewer redesign.

## 1. Feature Definition & Execution Plan

### Phase 1: Wire in `OrbitControls`
*   [x] `apps/tauri-ui/src/components/EnclosureViewer.tsx`: import `OrbitControls` from
    `@react-three/drei` (verified against the installed package's own `.d.ts` before writing the
    import — real, current export, not assumed from memory) and render it inside the existing
    `<Canvas>`, alongside the existing lights and mesh `<primitive>`. `makeDefault` (so other R3F
    hooks that expect a default controls instance find this one) and `enableDamping` (smoother,
    less jarring drag response) — no other props; the fixed initial camera position and FOV are
    unchanged.
*   [x] Deliberately not centering the orbit target on the mesh's own bounding box. FreeCAD's
    `Part::Box` is corner-anchored at the origin, not centered, so a `50×30×20mm` box's true center
    is `(25, 15, 10)`, not `(0, 0, 0)` — orbiting around the origin will look slightly off-center.
    Real, but a separate, smaller UX polish item from "there are no controls at all," which is the
    gap this context closes. Not fixed here.

### Phase 2: Give the `Canvas` a visible background — found by real human click-through
*   [x] Keith ran the real native app (hot-reloaded from Phase 1's change, same live session) and
    reported the fix worked, but "since the frame is black, it's hard to see the shading when
    rotating." `<Canvas>` never set a background at all, defaulting to pure black — rotating a flat
    grey mesh against a black void gives almost no contrast to actually see shading shift. Added
    `<color attach="background" args={['#3f3f46']} />` (the standard R3F idiom for setting
    `scene.background`), a dark neutral grey matching the app's existing theme rather than a
    jarring light background.

## 4. Plan Drift & Architectural Changes

*   **Non-deviation, confirmed as designed: this context is deliberately narrow.** `CTX-301.1`
    Deviation 5 named exactly one missing piece — no camera controls at all — and that's exactly
    what this context adds. The off-center orbit-target issue found while implementing this (see
    Phase 1) is real but distinct, and folding it in here would have re-created the same kind of
    scope-creep this repo's norms warn against; it's named explicitly rather than silently bundled
    in or silently dropped.
*   **Pre-existing debt flagged, not fixed, by `CTX-901.2`:** this context itself is the closest
    thing `SPEC-301` has to evidence for norm 9 — a real human rotating the shipped viewer, not a
    passing capability test, is what found the black-background/no-orbit gap this context fixes.
    Despite that, `SPEC-301` was never written with a "## 5. User & Interaction" section stating what
    the user is doing. `CTX-901.2` backfilled `user_facing: true` onto `SPEC-301`'s frontmatter and a
    TODO-marked stub rather than inventing that section after the fact. Recorded here per that
    context's own instruction to flag the gap in the CTX, not just the spec.
