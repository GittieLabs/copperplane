# CTX-311.8: Steeper default camera angle: the open-top cavity was occluded, not missing

> **Spec Reference:** Links to [SPEC-311](../specs/SPEC-311-enclosure-refinement-interactive-preview.md)

`CTX-311.7`'s real material fix worked -- the user's next screenshot showed a real, correctly-colored,
correctly-lit solid shape for the first time in this whole chain of fixes. The new complaint was
different in kind: "I can't see the inside corners or distinguish the floor in this view. I have to
rotate the enclosure to see the edges inside." A real, geometry-visible-but-poorly-framed problem,
not a rendering bug -- the enclosure was correctly shown as a real hollow, open-top shell the whole
time; the default camera angle just didn't reveal that.

## 1. Feature Definition & Execution Plan

### Phase 1: diagnosis
*   [x] The previous default polar angle (`acos(1/√3) ≈ 54.7°` from vertical -- a classic isometric
    "equal view of three faces" angle, the same angle that reproduced this viewer's own original
    `[80, 80, 80]` corner view) is a reasonable default for a *closed* solid, but this enclosure is a
    real, open-top hollow shell. At that shallow an elevation, the near wall of anything but a short,
    roughly-square shell occludes the opening almost entirely -- worse on a long, narrow board (the
    real board in the user's own screenshot), where the resulting silhouette reads as a plain solid
    wedge with no visible floor or interior corners at all, exactly as reported.

### Phase 2: fix
*   [x] `EnclosureViewer.tsx`: `DEFAULT_CAMERA_POLAR` lowered from the isometric `~54.7°` to a real,
    steeper `35°` from vertical -- a genuine 3/4 perspective (not a flat top-down `Top` preset view,
    which loses all sense of wall height/depth) that reveals the cavity and floor on first load for
    any real enclosure's proportions, not tuned to one board's own aspect ratio. `DEFAULT_CAMERA_
    AZIMUTH` and `DEFAULT_CAMERA_RADIUS` unchanged -- the reported problem was specifically about not
    seeing *down into* the shell, an elevation (polar) concern, not a left/right (azimuth) one.
*   [x] `Top`/`Bottom` camera presets (`CTX-311.3`) untouched -- they were already fully vertical and
    already showed the interior/floor correctly on their own; only the *default* 3/4 view needed to
    change.

### Phase 3: tests
*   [x] `sphericalToCartesian` tests updated: the old "reproduces `[80, 80, 80]`" assertion (a literal
    consequence of the old isometric polar angle, no longer true) replaced with two real, direct
    checks -- the new default polar produces a camera position where the vertical (Y) distance
    genuinely dominates the horizontal distance (a real "looking down into it" view, not just
    "steeper than before" asserted vaguely), and the new default polar sits strictly between a flat
    Top view (`0°`) and the old isometric angle, not accidentally reverted or over-corrected to
    fully top-down.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1: azimuth was deliberately left unchanged, even though the reported shape (an
    extreme, ~106mm x ~11.5mm board) plausibly also suffered some end-on foreshortening from the
    fixed 45° default azimuth, not just a shallow polar angle.** A per-board azimuth (e.g. derived
    from the loaded mesh's own real X/Z extents to favor a more "broadside" view of an elongated
    footprint) was considered but not built here -- the user's own words named the *floor* and
    *interior corners* specifically, which a polar-angle fix addresses directly and completely
    regardless of a board's real aspect ratio, while an azimuth fix would only help the specific
    "very long and thin" case and adds real complexity (deriving a "good" azimuth from arbitrary real
    footprints is a fuzzier problem than "look down more"). Left as a real, named follow-up if a
    future click-through shows the fixed azimuth still causing occlusion on similarly elongated
    boards, rather than solved speculatively now.
