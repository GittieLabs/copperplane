## 1. Feature Definition & Execution Plan

### Phase 1: mount `AgentChat` in `PartDetail.tsx`
*   [x] Mounted at the foot of the view (SPEC-318 §5's own "a collapsible chat panel at the foot of
    each area"), gated on `savedPart` -- there is no real `part_id` to scope a chat to before a Part
    is actually saved (matches SPEC-206 §2.2's own `scope="part"`, `scopeId` = `part_id`).
*   [x] `area="components"`, `projectName={currentProject?.name}` -- `undefined` when no project is
    open is a real, legitimate state (SPEC-318 §3's own named constraint, reachable directly via
    `PartDetail`'s own `initialPart`-via-Library entry point, `CTX-315.4`), never an error.
*   [x] `componentsPromotionTargets(partId, currentProject)`: always offers "this part" (a Part is a
    global `SPEC-304` object, so it's always a valid promotion target regardless of whether a project
    happens to be open); additionally offers "this project" when `currentProject` is set. A small,
    pure, independently-reasoned-about helper rather than inlining the branch into the JSX.

### Phase 2: tests
*   [x] `PartDetail.test.tsx` gains a stub for `./AgentChat` (matching `ComponentDiscovery.test.tsx`'s
    own existing precedent for stubbing `PartDetail` itself) -- keeps `PartDetail`'s own tests focused
    on *whether it wires AgentChat correctly* (real `scope`/`scopeId`/`area`/`title`/`projectName`/
    `promotionTargets`), not on AgentChat's own internals, which `AgentChat.test.tsx` (`CTX-318.1`)
    already covers directly.
*   [x] **Real bug caught by the stub, not by assumption:** before adding the stub, every existing
    `PartDetail` test rendered the *real* `AgentChat` unmocked the instant `savedPart` became truthy
    -- its own real `loadChatThread` call hit the real, unmocked `dispatch()`/`invoke()` with no Tauri
    runtime present, silently failing inside `AgentChat`'s own error state on every single test in the
    file rather than a clean, deliberate mock. All 71 pre-existing tests still reported "passed"
    throughout (the failure was fully contained to `AgentChat`'s own local `loadError` state), but it
    was real, unintended coupling -- fixed before it could mask a real regression in either component.

## 4. Plan Drift & Architectural Changes

*   **Deviation 1 (real, found while writing tests, not assumed): every pre-existing `PartDetail`
    test was unintentionally exercising the real, unmocked `AgentChat` the moment `savedPart` became
    truthy.**
    *   *Reasoning:* adding `AgentChat` to `PartDetail.tsx` without also adding a test-file mock for
        it left every existing test rendering the real component against a real, unmocked `dispatch()`
        call with no Tauri runtime present -- silently absorbed into `AgentChat`'s own local error
        state rather than failing loudly, so nothing in the test run's own pass/fail output would have
        surfaced it.
    *   *Impact:* fixed by adding the same kind of component-level stub `ComponentDiscovery.test.tsx`
        already established for `PartDetail` itself -- `PartDetail`'s own test suite no longer touches
        `AgentChat`'s internals at all, and a future change to `AgentChat`'s own real behavior can't
        silently break (or silently pass) a `PartDetail` test that never meant to exercise it.
